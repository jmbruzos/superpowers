# WRK-PLAN-MDM-MEMBER-EXIT-001 — La ficha que pierde un miembro se recalcula

## Approach

**Goal:** que la ficha `active` que pierde un miembro por un cierre de tramo en Persistence (ForceRule) quede, en la
misma transacción, recalculada con survivorship sobre sus miembros vigentes (o `orphaned` si no le queda ninguno),
sin pins al registro que salió y con un `field_lineage` que ya no lo cita.

**Architecture:** un `MemberSurvivorshipCalculator` en `mdm-ingest-service` (solo cálculo, puertos de `mdm-core`)
encapsula el encadenado `create`/`update` que hoy vive en `StewardshipService`. `PersistenceStepHandler` lo invoca
tras cada `move` sobre la ficha bloqueada que pierde el miembro y escribe el resultado; los eventos salen tras el
commit. Dos puertos: `SourceRecordVersionReader.findVersionsOfMembers` (ampliado) y `SourcePinWriter` (nuevo).

**Tech Stack:** Java 21, Spring Boot 3.4, Spring Data JPA/Hibernate, PostgreSQL 16, JUnit 5 + AssertJ + Mockito,
Testcontainers.

# WRK-SPEC-MDM-MEMBER-EXIT-001 — La ficha que pierde un miembro se recalcula

Cierra RFC-PIPE-039 y la OQ-4 de WRK-PLAN-MDM-SOURCE-IDENTITY-001 ("un movimiento por ForceRule (L → F) deja en L
los valores del registro que se fue hasta la siguiente re-survivorship"). Cluster `work:manual-unification`
(ADR-011); no toca el resto de RFCs del cluster (RFC-STEW-007, RFC-STEW-009, RFC-FE-029).

## Problem Statement

Cuando se cierra el tramo vigente de un registro de origen X en la xref (ADR-022 §2) y la ficha L que lo pierde
sigue `active`, los valores que ganaba X siguen en `golden_data` de L y su `field_lineage` sigue atribuyéndoselos a
X. Un consumidor lee en L un email o un NIF que ya vive en otra ficha.

Inventario de los sitios de producción que cierran tramos (lectura de código en `aacdae5`, 2026-09-29):

| Sitio | Operación | Qué pasa hoy con la ficha que pierde | ¿Defecto? |
|---|---|---|---|
| `PersistenceStepHandler.persistMembership` `:806` con `kind = FORCE_RULE` | ForceRule contradice el tramo (fila "F \| L ≠ F" de WRK-SPEC-MDM-SOURCE-IDENTITY-001 §2), o el merge llegó por `ABSORBED_INTO` desde F | `cleanUpAfterLosingMember` repone/borra claves y `refreshSourceCounts` baja `source_count`; `golden_data`, `field_lineage`, `quality_score` y `latest_source_received_at` de L **no cambian**; si X era su único miembro, L queda `active` con `source_count = 0` | **Sí** |
| `PersistenceStepHandler.persistMembership` `:806` con `kind = CONSOLIDATION` o `PIPELINE_RUN` (huérfana) | El merge siguió la absorción de L, o L no existe / está `deleted`/`orphaned` | L ya no está `active` | No |
| `PersistenceStepHandler.persistMembership` `:759` (`moveAllMembers`, consolidación ADR-021) | Absorción automática | Las absorbidas pasan a `merged` | No |
| `StewardshipService.manualMerge` `:995` (`moveAllMembers`) | Merge manual | Las absorbidas pasan a `absorbed` | No |
| `StewardshipService.writeUnmergeMembership` `:2288` | Unmerge | `unmerge` recalcula la original con `reSurvivorshipFromSources` (`:435`), reescribe `field_lineage` y desactiva los pins de los separados | No (el RFC lo cita, pero ya se recalcula) |
| Resolución de un caso de revisión | — | `ReviewQueueService.resolve` solo cambia el estado del caso; `MembershipOperationKind.REVIEW_RESOLUTION` no tiene llamadores | Aún no existe (WRK-SPEC 3, OQ-3 de WRK-SPEC-MDM-SOURCE-IDENTITY-001) |

Además, `StewardshipService` es el único dueño del algoritmo "survivorship sobre los miembros vigentes" (encadenado
`create` + `update` sobre todas las versiones en Silver, `reSurvivorshipFromSources` `:2875-2934`), y está en
`mdm-api-gateway`, que el pipeline (`mdm-ingest-service`) no puede usar.

## Decisiones (brainstorming 2026-09-29, aprobadas por human:ab-test)

- **D1 — Recálculo inmediato.** La ficha que pierde un miembro y sigue teniendo miembros vigentes se recalcula en la
  misma transacción que cierra el tramo, bajo el bloqueo de fila que esa transacción ya tiene. No se usa una marca
  de "pendiente de recálculo": dejaría a los lectores viendo el dato obsoleto que describe el RFC.
- **D2 — Recálculo completo, igual que re-survivorship.** Survivorship sobre todas las versiones en Silver de los
  miembros vigentes, en el orden determinista actual (`findVersionsOfMembers`), respetando overrides y pins activos.
  El resultado es idéntico al de `POST /admin/re-survivorship/{id}` sobre la misma ficha (DOM-MDM-SURVIVORSHIP-001
  §3.8.2). Se descarta recalcular solo los campos atribuidos al registro que salió: su resultado dependería de la
  historia de merges incrementales y divergiría del re-survivorship.
- **D3 — Sin miembros → `orphaned`.** Si el tramo cerrado era el último miembro vigente de una ficha `active`, la ficha
  pasa a `orphaned` (DOM-MDM-SURVIVORSHIP-001 §3.2: "`active → orphaned`: Cuando el último registro fuente se
  reasigna a otro GR"). Su `golden_data` y `field_lineage` se conservan como instantánea histórica: una ficha
  `orphaned` es "solo lectura histórica", no participa en matching y no se propaga. Sus blocking keys ya las borra
  `cleanUpAfterLosingMember`.
- **D4 — Pins al registro que salió.** Los source pins activos de la ficha que pierde el miembro y que apuntan al
  registro que salió (identidad completa; un pin legado sin fuente casa por id) se desactivan con motivo
  `auto_member_left`, igual que el unmerge desactiva los de los separados (DOM-MDM-PIPELINE-001 §10.6). Los
  `value_override` y los pins a otros miembros siguen activos y el recálculo los aplica.
- **D5 — También el superviviente de un merge manual.** La protección 409 de `reSurvivorship` (un recálculo
  discrecional borraría la decisión del steward) no aplica: aquí cambió la pertenencia y el dato viejo es incorrecto
  por definición. El unmerge ya recalcula la ficha original aunque sea superviviente de un merge manual.
- **D6 — Un único algoritmo.** El encadenado sale de `StewardshipService` a un componente compartido en
  `mdm-ingest-service`, que usan el pipeline y stewardship. Unmerge, re-survivorship y previews no cambian de
  comportamiento. Así, "pipeline ≡ re-survivorship" se cumple por construcción, y la resolución de revisión (WRK-SPEC 3)
  tiene dónde engancharse.

## Proposed Change

### 1. Componentes

**`MemberSurvivorshipCalculator`** (nuevo, `mdm-ingest-service`, paquete `com.mdm.ingest.survivorship`). Solo calcula:
no escribe nada. Depende solo de puertos de `mdm-core` y de componentes del propio módulo (E4 de
WRK-SPEC-MDM-SOURCE-IDENTITY-001):

| Método | Contrato |
|---|---|
| `static MergeResult chain(MergeEngine engine, List<MemberVersion> versions, SurvivorshipConfig cfg, String tenantId, String grId)` (E3) | El encadenado actual: primera versión `create`, el resto `update` sobre el acumulado; `trustScore` 1.0, `qualityScore` de la versión o 0.8, `pipelineRunId` `re-survivorship-<uuid>`. `null` si `versions` está vacía. |
| `Recomputation recompute(String tenantId, String entityType, String grId, Instant evaluationInstant)` | Miembros vigentes (`SourceMembershipRepository.findCurrentMembers`) → versiones (`SourceRecordVersionReader.findVersionsOfMembers`) → `SurvivorshipConfig` del schema activo → `chain` con el `MergeEngine` del contexto → `latestSourceReceivedAt` (`LatestSourceReceivedAtResolver`) → quality score (`QualityScoreResolver`). `members = 0` sin miembros vigentes; sin resultado si ninguno tiene versiones (E2). |

`Recomputation(int members, MergeResult result, QualityScoreResult quality, Instant latestSourceReceivedAt)`; `MemberVersion(String source, String sourceRecordId, Map<String, Object> normalizedData, BigDecimal qualityScore)`.

**`SourceRecordVersionReader`** (puerto existente, `mdm-core`) gana
`List<SourceRecordVersion> findVersionsOfMembers(String tenantId, String entityType, List<SourceRecordIdentity> members)`,
en el mismo orden que `StagedRecordJpaRepository#findVersionsOfMembers`. `SourceRecordVersion` gana
`BigDecimal qualityScore` (nullable).

**`SourcePinWriter`** (puerto nuevo, `mdm-core`; adaptador en `mdm-persistence`):
`List<DeactivatedPin> deactivateSourcePinsTo(String tenantId, String grId, SourceRecordIdentity departed, String reason, String actor, Instant at)`.
Devuelve `(field, pinnedSourceRecordId)` de cada pin desactivado.

**`PersistenceStepHandler`**: la "regla de la ficha que pierde un miembro" pasa de solo claves a claves + datos
(método `recomputeLosingGoldenRecord(ctx, previous, departed)`), invocada tras cada `move` de `persistMembership`:

1. `cleanUpAfterLosingMember` (claves; sin cambios).
2. Si la ficha bloqueada `previous` no está `active`: nada más (consolidación, huérfana ya tratada).
3. Desactiva los pins al registro que salió (D4) y programa `FieldOverrideAutoDeactivated` tras el commit.
4. `calculator.recompute(tenant, entityType, previous)`:
   - con resultado: escribe `golden_data`, `field_lineage`, `quality_score`, `latest_source_received_at`,
     `updated_at`, `updated_by = system:pipeline` sobre la entidad bloqueada y `saveAndFlush` (sube `@Version`);
     tras el commit emite `golden_record.updated` con `reason: member_left` y, si cambia el tier,
     `golden_record.quality_changed`;
   - vacío (no quedan miembros): `status = orphaned`, `updated_at`, `saveAndFlush`; tras el commit emite
     `golden_record.updated` con `reason: orphaned`.
5. `cacheEvictor.evictAfterCommit(previous)` (ya existe).

`StewardshipService`: su `reSurvivorshipFromSources` delega en `MemberSurvivorshipCalculator.chain` (mapeando
`StagedRecordEntity` a `MemberVersion`) sin cambiar firma ni orden; el resto de la clase no cambia.

**`IngestEventEmitter.emitGoldenRecordUpdated`** gana una sobrecarga con `reason` (clave de payload `reason`, mismo
nombre que en stewardship).

### 2. Flujo y transacción

Todo ocurre dentro de la transacción de Persistence (`PipelineOrchestrator` `transactionTemplate`, "atomic staged +
golden + index"). `previous` ya está bloqueada `FOR UPDATE` (`lockGoldenRecordsBeforeMove` o `lockGoldenRecord`)
antes del `move`, y el recálculo lee la xref **después** del `move`, así que el registro que salió no está entre los
miembros. Un fallo del recálculo (schema sin survivorship, error del motor) propaga y revierte toda la persistencia
(tramo, claves, staged, destino): no hay estado a medias. El orquestador lo trata como cualquier fallo de
Persistence (ADR-013). Un conflicto de `@Version` de L con una ingesta concurrente de otro miembro de L se resuelve
con el retroceso existente (ADR-020): quien pierde relee y fusiona sobre el dato recalculado.

### 3. Guarda de sitios de cierre

Un test de arquitectura enumera los llamadores de producción de `SourceMembershipRepository.move` y `moveAllMembers`
(hoy los cinco de la tabla del Problem Statement, en tres clases). Cada entrada declara cómo trata la ficha que
pierde: recalcula (esta regla), la retira (`merged`/`absorbed`) o ya no está activa. Un llamador nuevo, como la
resolución de revisión de WRK-SPEC 3, rompe el test hasta que se declare.

package com.mdm.persistence.repository;

import com.mdm.core.domain.membership.SourceRecordIdentity;
import com.mdm.core.repository.SourcePinWriter;
import com.mdm.persistence.entity.FieldOverrideRuleEntity;
import org.springframework.stereotype.Repository;

import java.time.Instant;
import java.util.ArrayList;
import java.util.List;
import java.util.UUID;

/**
 * Adaptador de {@link SourcePinWriter} sobre {@link FieldOverrideRuleJpaRepository}. Mismo criterio de coincidencia
 * que {@code StewardshipService.autoDeactivatePins}.
 *
 * @see <a href="specs/work/WRK-SPEC-MDM-MEMBER-EXIT-001-la-ficha-que-pierde-un-miembro-se-recalcula.md">D4</a>
 */
@Repository
public class SourcePinWriterAdapter implements SourcePinWriter {

    private static final String SOURCE_PIN = "SOURCE_PIN";

    private final FieldOverrideRuleJpaRepository repository;

    public SourcePinWriterAdapter(FieldOverrideRuleJpaRepository repository) {
        this.repository = repository;
    }

    /**
     * {@inheritDoc}
     */
    @Override
    public List<DeactivatedPin> deactivateSourcePinsTo(String tenantId, String goldenRecordId,
                                                       SourceRecordIdentity departed, String reason, String actor,
                                                       Instant at) {
        List<DeactivatedPin> deactivated = new ArrayList<>();
        for (FieldOverrideRuleEntity pin : repository.findByGoldenRecordIdAndTenantIdAndActiveAndOverrideType(
                UUID.fromString(goldenRecordId), tenantId, true, SOURCE_PIN)) {
            boolean sameId = departed.sourceRecordId().equals(pin.getPinnedSourceRecordId());
            boolean sameSource = pin.getPinnedSource() == null || pin.getPinnedSource().equals(departed.source());
            if (!sameId || !sameSource) {
                continue;
            }
            pin.setActive(false);
            pin.setDeactivatedAt(at);
            pin.setDeactivatedBy(actor);
            pin.setDeactivationReason(reason);
            repository.save(pin);
            deactivated.add(new DeactivatedPin(pin.getField(), pin.getPinnedSourceRecordId()));
        }
        return deactivated;
    }
}

# WRK-TASK-MDM-MEMBER-EXIT-001-002 — Calculadora de survivorship sobre los miembros vigentes

## Objective

D6 y E3 de la WRK-SPEC: un único algoritmo "survivorship sobre los miembros vigentes", usable desde el pipeline
(`mdm-ingest-service`) y desde stewardship (`mdm-api-gateway`, que depende de `mdm-ingest-service`).

- `MemberSurvivorshipCalculator.chain(...)` (estático) es el encadenado que hoy vive en
  `StewardshipService.reSurvivorshipFromSources(..., MergeEngine engine)` (`StewardshipService.java:2905-2934`),
  **idéntico**: primera versión `create`, el resto `update` sobre el acumulado, `trustScore` 1.0,
  `qualityScore` de la versión o 0.8, `pipelineRunId` `re-survivorship-<uuid>`, los tres últimos argumentos del
  `MergeRequest` a `null`.
- `recompute(...)` lee los miembros vigentes en la xref y sus versiones (puerto de la tarea 001), encadena con el
  `MergeEngine` del contexto y calcula frescura y quality score con los resolvers compartidos. No escribe nada.
- `StewardshipService` delega su encadenado en `chain` sin cambiar orden, conversión ni firma (AC7).

package com.mdm.ingest.survivorship;

import com.mdm.core.domain.membership.MembershipSpan;
import com.mdm.core.domain.membership.SourceRecordIdentity;
import com.mdm.core.domain.merge.MergeResult;
import com.mdm.core.domain.schema.SurvivorshipConfig;
import com.mdm.core.repository.SourceMembershipRepository;
import com.mdm.core.repository.SourceRecordVersionReader;
import com.mdm.core.repository.SourceRecordVersionReader.SourceRecordVersion;
import com.mdm.engine.merge.MergeEngine;
import com.mdm.engine.merge.MergeRequest;
import com.mdm.ingest.quality.LatestSourceReceivedAtResolver;
import com.mdm.ingest.quality.QualityScoreResolver;
import com.mdm.ingest.quality.QualityScoreResolver.QualityScoreInput;
import com.mdm.ingest.quality.QualityScoreResolver.QualityScoreResult;
import com.mdm.ingest.service.SchemaArtifactExtractor;
import com.mdm.schema.service.SchemaService;
import org.springframework.stereotype.Component;

import java.math.BigDecimal;
import java.time.Instant;
import java.util.List;
import java.util.Map;
import java.util.UUID;

/**
 * Survivorship sobre los miembros vigentes de un golden record (WRK-SPEC-MDM-MEMBER-EXIT-001 D2, D6): todas las
 * versiones en Silver de sus miembros, en el orden determinista de stewardship, encadenadas en el Merge Engine
 * (primera {@code create}, el resto {@code update} sobre el acumulado). Es el algoritmo de re-survivorship
 * (DOM-MDM-SURVIVORSHIP-001 §3.8.2) y del recálculo del unmerge (DOM-MDM-PIPELINE-001 §10.6 p.3); stewardship delega
 * en {@link #chain} y el pipeline usa {@link #recompute} para la ficha que pierde un miembro. Solo calcula: no
 * escribe nada.
 */
@Component
public class MemberSurvivorshipCalculator {

    /** Quality score de entrada de una version sin score de normalizacion (mismo valor que stewardship). */
    static final double DEFAULT_QUALITY_SCORE = 0.8;

    private final SourceMembershipRepository membershipRepository;
    private final SourceRecordVersionReader versionReader;
    private final SchemaService schemaService;
    private final SchemaArtifactExtractor schemaArtifactExtractor;
    private final MergeEngine mergeEngine;
    private final QualityScoreResolver qualityScoreResolver;
    private final LatestSourceReceivedAtResolver latestSourceReceivedAtResolver;

    public MemberSurvivorshipCalculator(SourceMembershipRepository membershipRepository,
                                        SourceRecordVersionReader versionReader,
                                        SchemaService schemaService,
                                        SchemaArtifactExtractor schemaArtifactExtractor,
                                        MergeEngine mergeEngine,
                                        QualityScoreResolver qualityScoreResolver,
                                        LatestSourceReceivedAtResolver latestSourceReceivedAtResolver) {
        this.membershipRepository = membershipRepository;
        this.versionReader = versionReader;
        this.schemaService = schemaService;
        this.schemaArtifactExtractor = schemaArtifactExtractor;
        this.mergeEngine = mergeEngine;
        this.qualityScoreResolver = qualityScoreResolver;
        this.latestSourceReceivedAtResolver = latestSourceReceivedAtResolver;
    }

    /**
     * Version de un miembro como entrada del encadenado. Vista neutra (sin {@link SourceRecordIdentity}) para que
     * stewardship pueda pasar filas legadas sin validar su fuente (WRK-SPEC-MDM-MEMBER-EXIT-001 E3).
     *
     * @param source         sistema de origen
     * @param sourceRecordId id del registro en su sistema
     * @param normalizedData datos normalizados de la version
     * @param qualityScore   quality score de normalizacion; {@code null} → {@value #DEFAULT_QUALITY_SCORE}
     */
    public record MemberVersion(String source, String sourceRecordId, Map<String, Object> normalizedData,
                                BigDecimal qualityScore) {}

    /**
     * Resultado del recalculo.
     *
     * @param members                miembros vigentes; 0 → la ficha se quedo sin miembros
     * @param result                 golden data y field lineage; {@code null} si no hay miembros o no tienen
     *                               versiones en Silver (E2)
     * @param quality                quality score del resultado; {@code null} sin resultado
     * @param latestSourceReceivedAt candidato unico de frescura de las versiones leidas
     */
    public record Recomputation(int members, MergeResult result, QualityScoreResult quality,
                                Instant latestSourceReceivedAt) {

        /** @return {@code true} si hay golden data recalculado */
        public boolean hasResult() {
            return result != null;
        }
    }

    /**
     * Encadena las versiones en el motor: la primera como {@code create}, cada siguiente como {@code update} sobre
     * el golden data y el field lineage acumulados.
     *
     * @return resultado del ultimo merge, o {@code null} si no hay versiones
     */
    public static MergeResult chain(MergeEngine engine, List<MemberVersion> versions, SurvivorshipConfig cfg,
                                    String tenantId, String goldenRecordId) {
        MergeResult result = null;
        for (MemberVersion v : versions) {
            boolean first = result == null;
            result = engine.merge(new MergeRequest(
                    first ? "create" : "update", v.normalizedData(),
                    first ? null : result.goldenData(), first ? null : result.fieldLineage(),
                    cfg, v.source(), v.sourceRecordId(),
                    1.0,
                    v.qualityScore() != null ? v.qualityScore().doubleValue() : DEFAULT_QUALITY_SCORE,
                    "re-survivorship-" + UUID.randomUUID(), goldenRecordId, tenantId,
                    null, null, null));
        }
        return result;
    }

    /**
     * Recalcula la ficha con survivorship sobre sus miembros vigentes en la xref, con el schema activo.
     *
     * @param evaluationInstant instante de evaluacion del quality score (frescura)
     */
    public Recomputation recompute(String tenantId, String entityType, String goldenRecordId,
                                   Instant evaluationInstant) {
        List<SourceRecordIdentity> members = membershipRepository.findCurrentMembers(tenantId, goldenRecordId)
                .stream().map(MembershipSpan::identity).distinct().toList();
        if (members.isEmpty()) {
            return new Recomputation(0, null, null, null);
        }
        List<SourceRecordVersion> versions = versionReader.findVersionsOfMembers(tenantId, entityType, members);
        if (versions.isEmpty()) {
            return new Recomputation(members.size(), null, null, null);
        }
        SurvivorshipConfig cfg = schemaArtifactExtractor.extractSurvivorshipConfig(
                schemaService.getActiveSchemaArtifacts(entityType, tenantId));
        MergeResult result = chain(mergeEngine, versions.stream()
                .map(v -> new MemberVersion(v.identity().source(), v.identity().sourceRecordId(),
                        v.normalizedData(), v.qualityScore()))
                .toList(), cfg, tenantId, goldenRecordId);
        Instant latest = latestSourceReceivedAtResolver.resolve(
                versions.stream().map(SourceRecordVersion::receivedAt).toList());
        QualityScoreResult quality = qualityScoreResolver.resolve(new QualityScoreInput(
                tenantId, entityType, result.goldenData(), result.fieldLineage(), latest, evaluationInstant));
        return new Recomputation(members.size(), result, quality, latest);
    }
}

# WRK-TASK-MDM-MEMBER-EXIT-001-003 — Persistence recalcula la ficha que pierde un miembro

## Objective

Cierra RFC-PIPE-039. En `PersistenceStepHandler.persistMembership` (`:803-810`), tras cada `move` de un registro
fuera de la ficha `previous`, la "regla de la ficha que pierde un miembro" deja de limitarse a las claves
(`cleanUpAfterLosingMember`) y además (WRK-SPEC §1, D1–D5):

1. si `previous` no está `active` → nada más (consolidación, huérfana; AC11);
2. desactiva los source pins de `previous` al registro que salió (`auto_member_left`) y, tras el commit, emite
   `FieldOverrideAutoDeactivated` por cada uno (AC4);
3. `MemberSurvivorshipCalculator.recompute(...)`:
   - con resultado → escribe `golden_data`, `field_lineage`, `quality_score`, `latest_source_received_at`,
     `updated_at`, `updated_by = system:pipeline` y `saveAndFlush`; tras el commit, `golden_record.updated` con
     `reason: member_left` y, si cambia el tier, `golden_record.quality_changed` (AC1, AC5);
   - `members == 0` → `status = orphaned`, sin tocar `golden_data`; tras el commit, `golden_record.updated` con
     `reason: orphaned` (AC3);
   - miembros sin versiones → no toca la ficha; WARN (E2).

Todo en la transacción de Persistence, antes de `refreshSourceCounts`. Un fallo del recálculo propaga (AC5).

    @Test
    void forceRuleMoveRecomputesTheLosingRecordOverItsRemainingMembers() throws Exception {
        String l = lima(T1);
        String f = foxtrot(T1);
        assertThat(lineageCites(T1, l, "erp_sap", "X2")).as("precondition: X2 wins fields of L").isTrue();
        assertThat(goldenData(l).path("email").asText()).isEqualTo(normalized(T1, "erp_sap", "X2").path("email").asText());
        int versionBefore = version(l);

        moveX2ToFoxtrot(T1, f);

        assertThat(lineageCites(T1, l, "erp_sap", "X2")).as("AC1: L's lineage no longer cites X2").isFalse();
        JsonNode data = goldenData(l);
        assertThat(data.path("phone").asText()).isEqualTo(normalized(T1, "crm", "X1").path("phone").asText());
        assertThat(data.path("email").isMissingNode() || data.path("email").isNull())
                .as("AC1: a field only X2 contributed disappears").isTrue();
        assertThat(version(l)).isGreaterThan(versionBefore);
        assertThat(sourceCount(l)).isEqualTo(1);
        assertThat(jdbc.queryForObject("SELECT updated_by FROM mdm_gold.golden_records WHERE id = ?::uuid",
                String.class, l)).isEqualTo("system:pipeline");

        // AC2 (E1): re-survivorship no cambia datos ni atribucion
        JsonNode lineageBefore = fieldLineage(l);
        mockMvc.perform(post("/api/v1/admin/re-survivorship/" + l)
                        .header("X-Tenant-Id", T1)
                        .header("X-User-Id", USER_ID))
                .andExpect(status().isOk());
        assertThat(goldenData(l)).isEqualTo(data);
        JsonNode lineageAfter = fieldLineage(l);
        assertThat(fieldNames(lineageAfter)).containsExactlyInAnyOrderElementsOf(fieldNames(lineageBefore));
        for (String field : fieldNames(lineageBefore)) {
            for (String attr : List.of("value", "source", "source_record_id")) {
                assertThat(lineageAfter.path(field).path(attr)).as("%s.%s", field, attr)
                        .isEqualTo(lineageBefore.path(field).path(attr));
            }
        }
    }

    @Test
    void lastMemberLeavingOrphansTheRecordAndKeepsItsSnapshot() throws Exception {
        String l = ingest(T1, "erp_sap", "X2", Map.of("legal_name", "Lima Logistica", "tax_id", "TL-9",
                "phone", "+34 611 000 009", "email", "x9@lima.es")).gr();
        String f = foxtrot(T1);
        JsonNode before = goldenData(l);

        moveX2ToFoxtrot(T1, f);

        assertThat(recordStatus(l)).isEqualTo("orphaned");
        assertThat(sourceCount(l)).isZero();
        assertThat(goldenData(l)).as("orphaned keeps its historical snapshot").isEqualTo(before);
        assertThat(jdbc.queryForObject("""
                SELECT count(*)::int FROM mdm_gold.blocking_key_entries WHERE tenant_id = ? AND golden_record_id = ?::uuid""",
                Integer.class, T1, l)).isZero();
        String z = ingest(T1, "web", "Z", Map.of("legal_name", "Lima Logistica", "tax_id", "TL-9",
                "phone", "+34 611 000 009", "email", "x9@lima.es")).gr();
        assertThat(z).as("an orphaned record is not a candidate").isNotEqualTo(l);
    }

        assertThat(sourceCount(l2)).isEqualTo(2);
    }

    /** ForceRule erp_sap/X2 → F y re-ingesta de X2 con datos de F: el tramo pasa de L a F. */

    private void registerSchema(String tenant, String version) throws Exception {
        JsonNode versioned = schema.deepCopy();
        ((ObjectNode) versioned.get("x-mdm")).put("version", version);
        mockMvc.perform(post("/api/v1/schemas")
                        .contentType(MediaType.APPLICATION_JSON)
                        .header("X-Tenant-Id", tenant)
                        .header("X-User-Id", USER_ID)
                        .content(objectMapper.writeValueAsString(Map.of("schema", versioned, "auto_activate", true))))
                .andExpect(status().isCreated());
    }

    private Ingested ingest(String tenant, String source, String srid, Map<String, Object> data) throws Exception {
        Map<String, Object> body = new LinkedHashMap<>();
        body.put("entity_type", ENTITY);
        body.put("source", source);
        body.put("source_record_id", srid);
        body.put("data", data);
        MvcResult r = mockMvc.perform(post("/api/v1/ingest/sync")
                        .contentType(MediaType.APPLICATION_JSON)
                        .header("X-Tenant-Id", tenant)
                        .header("X-User-Id", USER_ID)
                        .content(objectMapper.writeValueAsString(body)))
                .andReturn();
        assertThat(r.getResponse().getStatus()).as("ingest %s/%s in %s: %s", source, srid, tenant,
                r.getResponse().getContentAsString()).isEqualTo(200);
        JsonNode json = objectMapper.readTree(r.getResponse().getContentAsString());
        assertThat(json.path("status").asText()).as("ingest %s/%s in %s: %s", source, srid, tenant, json)
                .isEqualTo("completed");
        return new Ingested(json.get("golden_record_id").asText(), json);
    }

    private void manualMerge(String tenant, List<String> grs, String target) throws Exception {
        MvcResult r = mockMvc.perform(post("/api/v1/stewardship/manual-merge")
                        .contentType(MediaType.APPLICATION_JSON)
                        .header("X-Tenant-Id", tenant)
                        .header("X-User-Id", USER_ID)
                        .content(objectMapper.writeValueAsString(Map.of("golden_record_ids", grs,
                                "target_golden_record_id", target, "reason", "same supplier"))))
                .andReturn();
        assertThat(r.getResponse().getStatus()).as(r.getResponse().getContentAsString()).isEqualTo(200);
        evictAllCaches();
    }

    private void insertForceRule(String tenant, String source, String srid, String goldenRecordId) {
        jdbc.update("""
                INSERT INTO mdm_gold.force_rules
                    (tenant_id, entity_type, rule_type, source_record_id, source, golden_record_id, active, created_by)
                VALUES (?, ?, 'SOURCE_TO_GOLDEN', ?, ?, CAST(? AS uuid), true, 'test')""",
                tenant, ENTITY, srid, source, goldenRecordId);
        evictAllCaches();
    }

    private void insertPin(String tenant, String gr, String field, String source, String srid) {
        jdbc.update("""
                INSERT INTO mdm_gold.field_override_rules
                    (tenant_id, golden_record_id, entity_type, field, override_type, pinned_source_record_id,
                     pinned_source, active, created_by)
                VALUES (?, ?::uuid, ?, ?, 'SOURCE_PIN', ?, ?, true, 'test')""", tenant, gr, ENTITY, field, srid, source);
        evictAllCaches();
    }

    private void insertValueOverride(String tenant, String gr, String field, String value) throws Exception {
        jdbc.update("""
                INSERT INTO mdm_gold.field_override_rules
                    (tenant_id, golden_record_id, entity_type, field, override_type, value, active, created_by)
                VALUES (?, ?::uuid, ?, ?, 'VALUE_OVERRIDE', ?::jsonb, true, 'test')""",
                tenant, gr, ENTITY, field, objectMapper.writeValueAsString(value));
        evictAllCaches();
    }

    private Map<String, Object> rule(String tenant, String gr, String field) {
        return jdbc.queryForMap("""
                SELECT * FROM mdm_gold.field_override_rules WHERE tenant_id = ? AND golden_record_id = ?::uuid AND field = ?
                ORDER BY created_at DESC LIMIT 1""", tenant, gr, field);
    }

    /** Ultima version normalizada del registro en Silver. */
    private JsonNode normalized(String tenant, String source, String srid) throws Exception {
        return objectMapper.readTree(jdbc.queryForObject("""
                SELECT normalized_data::text FROM mdm_silver.staged_records
                WHERE tenant_id = ? AND source = ? AND source_record_id = ?
                ORDER BY coalesce(received_at, created_at) DESC, created_at DESC LIMIT 1""",
                String.class, tenant, source, srid));
    }

    private boolean lineageCites(String tenant, String gr, String source, String srid) throws Exception {
        JsonNode lineage = fieldLineage(gr);
        for (String field : fieldNames(lineage)) {
            JsonNode e = lineage.path(field);
            if (srid.equals(e.path("source_record_id").asText()) && source.equals(e.path("source").asText())) {
                return true;
            }
        }
        return false;
    }

    private static List<String> fieldNames(JsonNode node) {
        List<String> names = new java.util.ArrayList<>();
        for (Iterator<String> it = node.fieldNames(); it.hasNext(); ) names.add(it.next());
        return names;
    }

    private JsonNode goldenData(String gr) throws Exception {
        return objectMapper.readTree(jdbc.queryForObject(
                "SELECT golden_data::text FROM mdm_gold.golden_records WHERE id = ?", String.class, UUID.fromString(gr)));
    }

    private JsonNode fieldLineage(String gr) throws Exception {
        return objectMapper.readTree(jdbc.queryForObject(
                "SELECT field_lineage::text FROM mdm_gold.golden_records WHERE id = ?", String.class, UUID.fromString(gr)));
    }

    private int version(String gr) {
        return jdbc.queryForObject("SELECT version FROM mdm_gold.golden_records WHERE id = ?", Integer.class,
                UUID.fromString(gr));
    }

    private String recordStatus(String gr) {
        return jdbc.queryForObject("SELECT status FROM mdm_gold.golden_records WHERE id = ?", String.class,
                UUID.fromString(gr));
    }

    private int sourceCount(String gr) {
        return jdbc.queryForObject("SELECT source_count FROM mdm_gold.golden_records WHERE id = ?", Integer.class,
                UUID.fromString(gr));
    }
}

    /**
     * Regla de "ficha que pierde un miembro", parte de datos (WRK-SPEC-MDM-MEMBER-EXIT-001, RFC-PIPE-039): si la ficha
     * sigue {@code active}, desactiva sus source pins al registro que salio (D4) y la recalcula con survivorship sobre
     * sus miembros vigentes (D1, D2, D5). Sin miembros queda {@code orphaned} con su golden data como instantanea
     * historica (D3, DOM-MDM-SURVIVORSHIP-001 §3.2); con miembros sin versiones en Silver no se toca (E2). La ficha
     * ya esta bloqueada ({@code FOR UPDATE}) y la xref ya no incluye al registro que salio. Un fallo propaga y
     * revierte toda la persistencia; los eventos salen tras el commit.
     */
    private void recomputeLosingGoldenRecord(PipelineContext ctx, String previous, SourceRecordIdentity departed) {
        if (memberSurvivorship == null) {
            return;
        }
        GoldenRecordEntity gr = goldenRecordRepository.findById(UUID.fromString(previous)).orElse(null);
        if (gr == null || !GoldenRecordStatus.ACTIVE.getValue().equalsIgnoreCase(gr.getStatus())) {
            return;
        }
        String tenantId = ctx.getTenantId();
        String entityType = gr.getEntityType();
        Instant now = Instant.now();
        if (sourcePinWriter != null) {
            for (DeactivatedPin pin : sourcePinWriter.deactivateSourcePinsTo(tenantId, previous, departed,
                    AUTO_MEMBER_LEFT, SYSTEM_ACTOR, now)) {
                afterCommit(() -> ingestEventEmitter.emitFieldOverrideAutoDeactivated(previous, entityType,
                        pin.field(), "SOURCE_PIN", AUTO_MEMBER_LEFT, null, pin.pinnedSourceRecordId(),
                        ctx.getPipelineRunId(), ctx.getSource(), tenantId));
            }
        }
        Recomputation r = memberSurvivorship.recompute(tenantId, entityType, previous, now);
        if (r.members() == 0) {
            gr.setStatusEnum(GoldenRecordStatus.ORPHANED);
            gr.setUpdatedAt(now);
            gr.setUpdatedBy(SYSTEM_ACTOR);
            goldenRecordRepository.saveAndFlush(gr);
            afterCommit(() -> ingestEventEmitter.emitGoldenRecordUpdated(previous, entityType, ctx.getSource(),
                    tenantId, SYSTEM_ACTOR, "orphaned"));
            return;
        }
        if (!r.hasResult()) {
            log.warn("Golden record {} lost {} but none of its {} members has versions in Silver; not recomputed",
                    previous, departed.display(), r.members());
            return;
        }
        BigDecimal previousScore = gr.getQualityScore();
        gr.setGoldenData(objectMapper.valueToTree(r.result().goldenData()));
        gr.setFieldLineage(objectMapper.valueToTree(r.result().fieldLineage()));
        gr.setQualityScore(BigDecimal.valueOf(r.quality().score()));
        gr.setLatestSourceReceivedAt(r.latestSourceReceivedAt());
        gr.setUpdatedAt(now);
        gr.setUpdatedBy(SYSTEM_ACTOR);
        goldenRecordRepository.saveAndFlush(gr);
        afterCommit(() -> ingestEventEmitter.emitGoldenRecordUpdated(previous, entityType, ctx.getSource(), tenantId,
                SYSTEM_ACTOR, "member_left"));
        double before = previousScore != null ? previousScore.doubleValue() : 0.5;
        String beforeTier = qualityScoreResolver.tierFor(tenantId, entityType, before);
        QualityScoreResult after = r.quality();
        if (!beforeTier.equals(after.tier())) {
            afterCommit(() -> ingestEventEmitter.emitGoldenRecordQualityChanged(previous, entityType, before,
                    after.score(), beforeTier, after.tier(), ctx.getPipelineRunId(), ctx.getSource(), tenantId,
                    SYSTEM_ACTOR));
        }
    }

    /** Ejecuta tras el commit si hay transaccion; si no (tests sin sincronizacion), en el acto. */
    private static void afterCommit(Runnable action) {
        if (TransactionSynchronizationManager.isSynchronizationActive()) {
            TransactionSynchronizationManager.registerSynchronization(new TransactionSynchronization() {
                @Override public void afterCommit() { action.run(); }
            });
        } else {
            action.run();
        }
    }

# WRK-TASK-MDM-MEMBER-EXIT-001-004 — Concurrencia, reversión, regresión del unmerge y guarda

## Objective

Hardening of task 003; production code does not change here unless a test exposes a defect (in that case: stop,
record it in the plan's Execution Log and fix it in this task with its own commit).

- **AC8**: the ForceRule move of X2 out of L and a re-ingest of the other member X1 of L are held on L's row lock
  and released together. Whatever order they commit in, L ends up as survivorship over its current members (X1's
  new version included), and its lineage does not cite X2.
- **AC5** (IT part): if the recompute fails, nothing of the moving run persists: X2's span, its keys and
  `source_count` stay as before.
- **AC7** (new regression IT): after an unmerge, no `field_lineage` entry of the original cites a separated record.
- **AC10**: an architecture test fails when a production caller of `move`/`moveAllMembers` appears that is not
  declared together with how it treats the losing golden record.

/**
 * Guarda de AC10 (WRK-SPEC-MDM-MEMBER-EXIT-001 §3): todo codigo de produccion que cierra tramos de la xref
 * ({@code SourceMembershipRepository.move}/{@code moveAllMembers}) esta declarado aqui junto con lo que hace con la

class MemberExitCallSitesGuardTest {

    private static final Pattern CALL = Pattern.compile("\\.(move|moveAllMembers)\\s*\\(");
    private static final String PORT_IMPORT = "import com.mdm.core.repository.SourceMembershipRepository;";

    /** Fichero → numero de llamadas. Cada una, con su tratamiento de la ficha que pierde el miembro. */
    private static final Map<String, Integer> DECLARED = Map.of(
            // move: ForceRule → recomputeLosingGoldenRecord; consolidacion/huerfana → la ficha ya no esta activa.
            // moveAllMembers: consolidacion ADR-021 → las absorbidas pasan a merged.
            "PersistenceStepHandler.java", 2,
            // move: unmerge → reSurvivorshipFromSources recalcula la original.
            // moveAllMembers: merge manual → las absorbidas pasan a absorbed.
            "StewardshipService.java", 2);

    @Test
    void everyProductionCallSiteThatClosesSpansIsDeclared() throws IOException {
        Path root = Path.of("..").toAbsolutePath().normalize(); // src/
        Map<String, Integer> found = new TreeMap<>();
        try (Stream<Path> files = Files.walk(root)) {
            files.filter(p -> p.toString().endsWith(".java"))
                    .filter(p -> p.toString().contains("/src/main/"))
                    .filter(p -> !p.toString().contains("/target/"))
                    .filter(p -> !p.toString().contains("/node_modules/"))
                    .forEach(p -> {
                        String code = read(p);
                        if (!code.contains(PORT_IMPORT)) return;
                        Matcher m = CALL.matcher(code);
                        int n = 0;
                        while (m.find()) n++;
                        if (n > 0) found.put(p.getFileName().toString(), n);
                    });
        }
        assertThat(found).as("AC10: declare every caller of move/moveAllMembers and its losing-record treatment")
                .isEqualTo(new TreeMap<>(DECLARED));
    }

    private static String read(Path path) {
        try {
            return Files.readString(path);
        } catch (IOException e) {
            throw new UncheckedIOException(e);
        }
    }

    /** Espera (conexion propia) a que al menos {@code n} sesiones esperen un bloqueo. */
    private void awaitSessionsWaitingOnLock(int n) {
        long deadline = System.nanoTime() + TimeUnit.SECONDS.toNanos(20);
        try (Connection c = dataSource.getConnection()) {
            while (System.nanoTime() < deadline) {
                try (ResultSet rs = c.createStatement().executeQuery("""
                        SELECT count(*) FROM pg_stat_activity
                        WHERE datname = current_database() AND wait_event_type = 'Lock'""")) {
                    rs.next();
                    if (rs.getLong(1) >= n) return;
                }
                Thread.sleep(50);
            }
        } catch (Exception e) {
            throw new IllegalStateException(e);
        }
        throw new IllegalStateException("fewer than " + n + " sessions waited on a lock within 20 s");
    }

    private JsonNode normalized(String source, String srid) throws Exception {
        return objectMapper.readTree(jdbc.queryForObject("""
                SELECT normalized_data::text FROM mdm_silver.staged_records
                WHERE tenant_id = ? AND source = ? AND source_record_id = ?
                ORDER BY coalesce(received_at, created_at) DESC, created_at DESC LIMIT 1""",
                String.class, T, source, srid));
    }

    private boolean lineageCites(String gr, String source, String srid) throws Exception {
        JsonNode lineage = objectMapper.readTree(jdbc.queryForObject(
                "SELECT field_lineage::text FROM mdm_gold.golden_records WHERE id = ?", String.class,
                UUID.fromString(gr)));
        List<String> fields = new ArrayList<>();
        for (Iterator<String> it = lineage.fieldNames(); it.hasNext(); ) fields.add(it.next());
        return fields.stream().map(lineage::path).anyMatch(e ->
                srid.equals(e.path("source_record_id").asText()) && source.equals(e.path("source").asText()));
    }

    private JsonNode goldenData(String gr) throws Exception {
        return objectMapper.readTree(jdbc.queryForObject(
                "SELECT golden_data::text FROM mdm_gold.golden_records WHERE id = ?", String.class, UUID.fromString(gr)));
    }

    private int version(String gr) {
        return jdbc.queryForObject("SELECT version FROM mdm_gold.golden_records WHERE id = ?", Integer.class,
                UUID.fromString(gr));
    }

    private int sourceCount(String gr) {
        return jdbc.queryForObject("SELECT source_count FROM mdm_gold.golden_records WHERE id = ?", Integer.class,
                UUID.fromString(gr));
    }
