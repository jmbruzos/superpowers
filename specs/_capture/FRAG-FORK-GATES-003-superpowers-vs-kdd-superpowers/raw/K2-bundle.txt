# WRK-PLAN-MDM-MEMBER-LOSS-001 — La ficha que pierde un miembro se recalcula

> **For agentic workers:** REQUIRED SUB-SKILL: Use kdd-superpowers:subagent-driven-development (recommended) or kdd-superpowers:executing-plans to implement this plan task-by-task. Each task is its own WRK-TASK file under `specs/work/`; steps use checkbox (`- [ ]`) syntax for tracking.

## Approach

**Goal:** que la ficha que pierde un miembro por una ForceRule quede recalculada con survivorship sobre sus miembros
vigentes (u `orphaned` si no le quedan), sin linaje hacia el registro que salió, en la misma transacción que el
movimiento; y que el unmerge, que ya lo hace, comparta el mismo algoritmo.

**Architecture:** un único merge encadenado sobre un conjunto de miembros (`MemberSetSurvivorship`, en
`mdm-ingest-service`) que usan stewardship y el pipeline. El paso Merge calcula la ficha que pierde el miembro
(`LosingGoldenRecordRecomputer`) cuando la resolución de pertenencia es `FORCED` con conflicto; el paso Persistence la
escribe bajo el `FOR UPDATE` que ya toma, con guarda de versión, estado y miembros, y la marca para que
`IngestService`/`AsyncPipelineExecutor` emitan `golden_record.updated` tras el commit.

**Tech Stack:** Java 21, Spring Boot 3.4, Spring Data JPA, JUnit 5 + AssertJ + Mockito, Testcontainers PostgreSQL.
Maven desde `src/`.

**Spec:** `specs/work/WRK-SPEC-MDM-MEMBER-LOSS-001-la-ficha-que-pierde-un-miembro-se-recalcula.md` — el plan argumenta
desde la spec; los ejecutores leen las dos.

# WRK-SPEC-MDM-MEMBER-LOSS-001 — La ficha que pierde un miembro se recalcula

## Problem Statement

RFC-PIPE-039: cuando un registro de origen sale de un golden record (se cierra su tramo en la xref), la ficha que lo
pierde retira sus blocking keys y baja `source_count`, pero su `golden_data` y su `field_lineage` no se recalculan:
los campos que ganaba el registro que salió siguen mostrando su valor y el linaje sigue atribuyéndoselo. Un
consumidor puede leer un email o un NIF que ya vive en otra ficha.

Lo que el código hace hoy (ver *Code Premises*):

- **ForceRule** (fila "F | L ≠ F" de la resolución de pertenencia, ADR-022): `PersistenceStepHandler.persistMembership`
  cierra el tramo en L, abre en F y llama a `cleanUpAfterLosingMember(L)`, que solo repone y poda blocking keys. L
  queda `active` con datos del registro que se fue; si era su último miembro, queda `active` con `source_count = 0`.
  Nada publica `golden_record.updated` para L.
- **Seguimiento de absorción** (`consolidation`) y **reparación de huérfano** (`pipeline_run`, `membership_orphan`):
  mismo punto de código, pero la ficha que pierde el miembro ya no es `active` (absorbida, borrada, huérfana o
  inexistente); no hay datos vigentes que corregir.
- **Unmerge**: `StewardshipService.unmerge` ya recalcula la ficha original desde cero sobre los miembros que quedan
  (DOM-MDM-PIPELINE-001 §10.6 p.3). Es la implementación de referencia; sin test que lo afirme sobre el linaje.
- **Resolución de revisión**: `MembershipOperationKind.REVIEW_RESOLUTION` no tiene productor; no hay camino de código
  que cerrar (OQ-3 de WRK-SPEC-MDM-SOURCE-IDENTITY-001 sigue en su cluster).

## Proposed Change

### Arquitectura

Un único cálculo de survivorship sobre un conjunto de miembros, compartido por stewardship y el pipeline, y una regla
de "ficha que pierde un miembro" que lo aplica **síncronamente, en la transacción de Persistence y bajo el bloqueo
`FOR UPDATE` que ya se toma** sobre esa ficha. Si algo falla, la transacción entera se revierte y aplica el reintento
normal (DOM-MDM-PIPELINE-001 §6.5, ADR-013): nunca queda visible una ficha con el miembro fuera y los datos dentro.

Alternativas descartadas: marca `needs_resurvivorship` + barrido (consistencia eventual, migración y proceso nuevo, la
ventana de lectura obsoleta sigue existiendo); recálculo por evento tras el commit (los eventos son best-effort: un
evento perdido deja la ficha obsoleta para siempre).

### Componentes

1. **`MemberSetSurvivorship`** (nuevo, `mdm-ingest-service`, paquete `com.mdm.ingest.survivorship`). Contiene el
   algoritmo que hoy es `StewardshipService.reSurvivorshipFromSources`: merge encadenado sobre una lista ordenada de
   versiones de miembros — la primera en modo `create`, el resto `update` sobre el resultado acumulado — con el
   `MergeEngine` inyectado (nunca uno propio: perdería los overrides activos, PROD-MDM-STEWARDSHIP-001 §3.8.5). Acepta
   un `MergeEngine` explícito para los previews. Entrada: `tenantId`, `goldenRecordId`, `SurvivorshipConfig` y la
   lista de versiones (`source`, `source_record_id`, `normalizedData`, `qualityScore`); salida: `MergeResult`, o
   `null` si la lista está vacía. `StewardshipService.reSurvivorshipFromSources` (las dos sobrecargas) delega en él
   convirtiendo sus `StagedRecordEntity`, sin cambiar firma ni resultado: unmerge, previews, re-survivorship,
   corrección y overrides pasan a usar el mismo código que el pipeline.
2. **`SourceRecordVersionReader.findVersionsOfMembers(tenantId, entityType, identities)`** (método nuevo del puerto
   existente de `mdm-core`, implementado en `SourceRecordVersionReaderAdapter` sobre
   `StagedRecordJpaRepository.findVersionsOfMembers`, mismo orden determinista). `SourceRecordVersion` gana
   `qualityScore` (`Double`, nulo si Silver no lo tiene). El código nuevo de `mdm-ingest-service` no importa JPA
   (regla del proyecto; E4 de WRK-SPEC-MDM-SOURCE-IDENTITY-001).
3. **`LosingGoldenRecordRecomputer`** (nuevo, `mdm-ingest-service`). Lo invoca
   `PersistenceStepHandler.cleanUpAfterLosingMember` después de reponer y podar las claves, con la ficha ya bloqueada.
   Recibe la fila bloqueada (`GoldenRecordEntity`), los miembros vigentes y el `SurvivorshipConfig` del contexto (la
   identidad del registro incluye `entity_type`: la ficha que lo pierde es del mismo tipo que el registro entrante).

   | Estado de la ficha que pierde el miembro | Miembros vigentes | Acción |
   |---|---|---|
   | no `active` (`merged`/`absorbed`/`deleted`/`orphaned`) o inexistente | — | Nada (hoy igual) |
   | `active` | ≥ 1 | Recalcula `golden_data` y `field_lineage` con `MemberSetSurvivorship` sobre todas las versiones en Silver de los miembros vigentes; `latest_source_received_at` = `LatestSourceReceivedAtResolver.resolve` sobre esas versiones; `quality_score` con `QualityScoreResolver` (instante de evaluación: `Instant.now()` de este paso); `source_count` = número de miembros; `updated_at`; `saveAndFlush` (incrementa `@Version`) |
   | `active` | 0 | `active → orphaned` (DOM-MDM-SURVIVORSHIP-001 §3.2); `golden_data = {}`, `field_lineage = {}`, `quality_score` y `latest_source_received_at` a `NULL`, `source_count = 0`; `saveAndFlush` |

   Se escribe aunque el resultado sea idéntico (la ficha acaba de cambiar de miembros; la versión debe moverse para
   que una lectura cacheada con la versión anterior choque, ADR-020). El recálculo se aplica también si la ficha es
   superviviente de un merge manual (ForceRule `GOLDEN_TO_GOLDEN` activa): la exclusión de PROD-MDM-STEWARDSHIP-001
   §3.8.5 protege el re-survivorship que lanza un operador, no un cambio de pertenencia; los miembros absorbidos son
   miembros vigentes y entran en el cálculo.
4. **Orden en `persistMembership`**: bloqueo → `move` → claves → **recálculo de la ficha que pierde el miembro** →
   `refreshSourceCounts`. El recálculo escribe antes del `UPDATE` nativo de `source_count` y deja además
   `source_count` coherente por sí mismo, de modo que ninguna escritura posterior de la entidad lo retrocede.
5. **Eventos y caché**. `PipelineContext` acumula los ids de las fichas recalculadas u orfanadas
   (`losingGoldenRecordIds`). Tras el commit, `IngestService` y `AsyncPipelineExecutor` emiten
   `golden_record.updated` por cada una (junto a la emisión que ya hacen para la ficha del contexto): es el evento
   canónico que consume `CacheInvalidationListener` en los demás pods (ARCH-MDM-PERFORMANCE-001 §3.3.1). La
   evicción in-process `cacheEvictor.evictAfterCommit(previous)` se mantiene. Un cruce de tier del score de esa ficha
   emite `GoldenRecordQualityChanged` con el mismo criterio que el pipeline aplica hoy a la ficha escrita
   (DOM-MDM-SURVIVORSHIP-001 §3.7.3; una ficha que pasa a `orphaned` no emite cambio de calidad).

### Flujo de datos

```
Match (resolución de pertenencia: FORCED, L ≠ F)
  → Merge (fusiona el entrante en F, como hoy)
  → Persistence [una transacción]
       lock(F, L) · persist F · move(identidad, L→F) · claves de L
       · LosingGoldenRecordRecomputer(L): versiones de los miembros vigentes de L → MemberSetSurvivorship
         → QualityScoreResolver → save(L)   |   0 miembros → L orphaned
       · refreshSourceCounts(F, L)
  → commit → evict(F), evict(L) · golden_record.updated(F), golden_record.updated(L)
```

### Manejo de errores

Cualquier excepción del recálculo (p. ej. un tipo de entidad sin schema activo, un fallo de lectura de Silver) se
propaga: la transacción de Persistence se revierte entera y el orquestador aplica su política de reintentos
(DOM-MDM-PIPELINE-001 §6.5, ADR-013). No se captura ni se degrada a "solo claves": dejar la ficha con datos del
registro que salió es precisamente el defecto. Un conflicto de bloqueo sigue traduciéndose a
`OptimisticLockingFailureException` como hoy.

### Pruebas

- **Unitarios** `LosingGoldenRecordRecomputerTest`: las tres filas de la tabla; el valor ganado por el registro que
  salió se sustituye por el del miembro restante; `field_lineage` sin entradas con el `source_record_id` que salió;
  `source_count`; ficha no `active` intacta; orfanada con `{}`.
- **Unitarios** `MemberSetSurvivorshipTest`: lista vacía → `null`; uno → `create`; varios → encadenado en orden.
- **Unitarios** `PersistenceStepHandlerTest`: el movimiento por ForceRule invoca el recálculo de L después de las
  claves y antes de `refreshSourceCounts`; el seguimiento de absorción y el huérfano no escriben la ficha no activa;
  `losingGoldenRecordIds` contiene L.
- **Paridad** `StewardshipServiceTest` (EngineServiceScoreParity y los tests existentes de unmerge/re-survivorship)
  en verde sin cambiar sus expectativas tras la delegación.
- **IT** (`SourceIdentityPipelineIT`, Testcontainers PostgreSQL): L con X1 (`crm`, email a) y X2 (`erp`, email b),
  regla `source_priority` que hace ganar a X1; ForceRule mueve X1 a F; re-ingesta de X1 → L muestra email b, su
  `field_lineage.email.source_record_id` es X2, ninguna entrada de L nombra a X1, versión incrementada,
  `source_count = 1`, y `POST /admin/re-survivorship/{L}` sobre el resultado informa `changed = 0`. Segundo caso:
  ForceRule mueve el único miembro de L → L `orphaned`, `golden_data = {}`, `source_count = 0`.
- **IT** unmerge (`StewardshipMembershipIT`): tras separar el registro que ganaba un campo, la ficha original no
  tiene entradas de `field_lineage` con su `source_record_id` y muestra el valor del miembro restante.

    @Override
    public List<SourceRecordVersion> findVersionsOfMembers(String tenantId, String entityType,
                                                           List<SourceRecordIdentity> members) {
        if (members.isEmpty()) {
            return List.of();
        }
        String[] sources = members.stream().map(SourceRecordIdentity::source).toArray(String[]::new);
        String[] srids = members.stream().map(SourceRecordIdentity::sourceRecordId).toArray(String[]::new);
        return repository.findVersionsOfMembers(tenantId, entityType, sources, srids).stream()
                .map(entity -> toSourceRecordVersion(new SourceRecordIdentity(tenantId, entityType,

import com.mdm.core.domain.merge.MergeResult;
import com.mdm.core.domain.schema.SurvivorshipConfig;
import com.mdm.engine.merge.MergeEngine;
import com.mdm.engine.merge.MergeRequest;

import java.util.Map;
import java.util.UUID;

/**
 * Survivorship completo de un golden record sobre un conjunto de versiones de sus miembros: merge encadenado, la
 * primera version en modo {@code create} y el resto en {@code update} sobre el resultado acumulado. Unico algoritmo
 * para stewardship (unmerge, previews, re-survivorship, correcciones, overrides) y para el pipeline (ficha que pierde
 * un miembro). Sin estado: el {@link MergeEngine} lo pasa el llamante, y debe ser el bean inyectado (o uno explicito
 * de preview) para no perder los overrides activos (PROD-MDM-STEWARDSHIP-001 §3.8.5).
 *
 * @see <a href="specs/work/WRK-SPEC-MDM-MEMBER-LOSS-001-la-ficha-que-pierde-un-miembro-se-recalcula.md">WRK-SPEC-MDM-MEMBER-LOSS-001, Componentes 1</a>
 */
public final class MemberSetSurvivorship {

    /** Quality score de una version sin {@code staged_records.quality_score} (mismo valor que stewardship). */
    public static final double DEFAULT_QUALITY_SCORE = 0.8;

    /**
     * Version de un miembro tal como entra al merge.
     *
     * @param source         sistema de origen
     * @param sourceRecordId id del registro en su sistema de origen
     * @param data           campos normalizados de la version
     * @param qualityScore   quality score de la version en Silver ({@code null} → {@link #DEFAULT_QUALITY_SCORE})
     */
    public record MemberVersion(String source, String sourceRecordId, Map<String, Object> data, Double qualityScore) {}

    /**
     * @param engine             motor de merge (el bean inyectado, o uno de preview)
     * @param versions           versiones en el orden en que se fusionan
     * @param survivorshipConfig reglas de survivorship del tipo de entidad
     * @param tenantId           tenant
     * @param goldenRecordId     ficha que se calcula (la usa el {@code FieldOverrideProvider})
     * @param runLabelPrefix     prefijo del {@code pipelineRunId} de cada paso
     * @return resultado del ultimo paso, o {@code null} si no hay versiones
     */
    public MergeResult survive(MergeEngine engine, List<MemberVersion> versions, SurvivorshipConfig survivorshipConfig,
                               String tenantId, String goldenRecordId, String runLabelPrefix) {
        if (versions.isEmpty()) {
            return null;
        }
        MergeResult result = null;
        for (int i = 0; i < versions.size(); i++) {
            MemberVersion v = versions.get(i);
            MergeRequest request = new MergeRequest(
                    i == 0 ? "create" : "update", v.data(),
                    result != null ? result.goldenData() : null,
                    result != null ? result.fieldLineage() : null,
                    survivorshipConfig, v.source(), v.sourceRecordId(),
                    1.0,
                    v.qualityScore() != null ? v.qualityScore() : DEFAULT_QUALITY_SCORE,
                    runLabelPrefix + UUID.randomUUID(), goldenRecordId, tenantId,
                    null, null, null);
            result = engine.merge(request);
        }
        return result;
    }
}

# WRK-TASK-MDM-MEMBER-LOSS-001-003 — Cálculo de la ficha que pierde un miembro en Merge

## Objective

Cuando la resolución de pertenencia es `FORCED` con `conflictFromGoldenRecordId = L` y el merge escribe otra ficha, el
paso Merge calcula L sin el registro entrante (spec, Componentes 3; DOM-MDM-PIPELINE-001 §6.5 Propósito y §10.8.4
"Cálculo: Dos operaciones de merge puro"). El resultado viaja en `PipelineContext` hasta Persistence (tarea 004) y se
borra en cada retroceso (`clearMergeOutput`, spec AC6).

                                        QualityScoreResolver qualityScoreResolver,
                                        LatestSourceReceivedAtResolver latestSourceReceivedAtResolver) {
        this.mergeEngine = mergeEngine;
        this.membershipRepository = membershipRepository;
        this.versionReader = versionReader;
        this.qualityScoreResolver = qualityScoreResolver;
        this.latestSourceReceivedAtResolver = latestSourceReceivedAtResolver;
    }

    /**
     * @param losing             la ficha que pierde el miembro, tal como la leyo el merge ({@code null} si no existe)
     * @param leaving            identidad del registro que sale
     * @param survivorshipConfig reglas del tipo de entidad del registro (el mismo que el de la ficha)
     * @param evaluationInstant  instante de evaluacion del score, el mismo que el merge de la ficha destino
     * @return el calculo, o vacio si la ficha no existe, no esta activa o no trae version (Persistence lo tratara
     *         como conflicto si la encuentra activa)
     */
    public Optional<LosingGoldenRecordRecompute> compute(GoldenRecordFullData losing, SourceRecordIdentity leaving,
                                                         SurvivorshipConfig survivorshipConfig,
                                                         Instant evaluationInstant) {
        if (losing == null || losing.version() == null || !isActive(losing.status())) {
            return Optional.empty();
        }
        String tenantId = leaving.tenantId();
        String entityType = leaving.entityType();
        List<SourceRecordIdentity> remaining = membershipRepository.findCurrentMembers(tenantId, losing.id()).stream()
                .map(MembershipSpan::identity)
                .filter(id -> !id.equals(leaving))
                .distinct()
                .toList();
        if (remaining.isEmpty()) {
            return Optional.of(LosingGoldenRecordRecompute.orphan(losing.id(), losing.version(),
                    losing.qualityScore()));
        }
        List<SourceRecordVersion> versions = versionReader.findVersionsOfMembers(tenantId, entityType, remaining);
        List<MemberSetSurvivorship.MemberVersion> input = versions.stream()
                .map(v -> new MemberSetSurvivorship.MemberVersion(v.identity().source(), v.identity().sourceRecordId(),
                        v.normalizedData(), v.qualityScore()))
                .toList();
        MergeResult result = memberSetSurvivorship.survive(mergeEngine, input, survivorshipConfig, tenantId,
                losing.id(), "member-loss-");
        if (result == null) {
            throw new PipelineException(PipelineException.STEP_FAILED, "Golden record " + losing.id()
                    + " keeps members " + remaining + " without versions in Silver", "merge");
        }
        Instant latestSourceReceivedAt = latestSourceReceivedAtResolver.resolve(
                versions.stream().map(SourceRecordVersion::receivedAt).toList());
        QualityScoreResult score = qualityScoreResolver.resolve(new QualityScoreInput(tenantId, entityType,
                result.goldenData(), result.fieldLineage(), latestSourceReceivedAt, evaluationInstant));
        return Optional.of(new LosingGoldenRecordRecompute(losing.id(), losing.version(),
                LosingGoldenRecordRecompute.Kind.RECOMPUTE, result.goldenData(), result.fieldLineage(),
                latestSourceReceivedAt, score, losing.qualityScore(), Set.copyOf(remaining)));
    }

    /** Mismo criterio que {@code PersistenceStepHandler}: sin estado cuenta como activa. */
    private static boolean isActive(String status) {
        return status == null || GoldenRecordStatus.ACTIVE.getValue().equalsIgnoreCase(status);
    }
}
```

     * Ficha L que perdera el registro entrante por una ForceRule (resolucion FORCED con conflicto desde L y merge
     * hacia otra ficha): se calcula aqui, como el "calculo puro" de DOM-MDM-PIPELINE-001 §10.8.4, y Persistence la
     * escribe con guarda de version (WRK-SPEC-MDM-MEMBER-LOSS-001, Componentes 3-4).
     */
    private LosingGoldenRecordRecompute computeLosingGoldenRecord(PipelineContext ctx, GoldenRecordFullData target,
                                                                  Instant evaluationInstant) {
        if (losingRecomputer == null || target == null || ctx.getMatchResponse() == null) {
            return null;
        }
        MembershipResolution m = ctx.getMatchResponse().membership();
        String losingId = m.conflictFromGoldenRecordId();
        SourceRecordIdentity leaving = incomingIdentity(ctx);
        if (m.kind() != MembershipResolution.Kind.FORCED || losingId == null || losingId.equals(target.id())
                || leaving == null) {
            return null;
        }
        GoldenRecordFullData losing = lookup(ctx, List.of(losingId)).stream().findFirst().orElse(null);
        return losingRecomputer.compute(losing, leaving, ctx.getSurvivorshipConfig(), evaluationInstant).orElse(null);
    }

# WRK-TASK-MDM-MEMBER-LOSS-001-004 — Escritura de la ficha que pierde un miembro

## Objective

En la rama `FORCE_RULE` de `PersistenceStepHandler.persistMembership`, tras el `move` y la limpieza de claves y antes
de `refreshSourceCounts`, escribir la ficha L con el cálculo que dejó el paso Merge (tarea 003), bajo el `FOR UPDATE`
que ya se toma y con guarda de versión, estado y miembros (spec, Componentes 4). Una L que pierde su último miembro pasa
a `orphaned`. El cambio de tier de L se emite con el score de L. Persistence marca L en
`ctx.addLosingGoldenRecordId` para la tarea 005.

    /**
     * Regla de "ficha que pierde un miembro" (WRK-SPEC-MDM-MEMBER-LOSS-001, Componentes 4): escribe L con el calculo
     * que dejo el paso Merge si L sigue activa, en la version que leyo ese calculo y con exactamente sus miembros
     * vigentes tras el {@code move}; si no, conflicto y retroceso a Merge (DOM-MDM-PIPELINE-001 §6.5 p.3). Sin
     * miembros, L pasa a {@code orphaned} (DOM-MDM-SURVIVORSHIP-001 §3.2). Se ejecuta antes de
     * {@code refreshSourceCounts} y deja {@code source_count} coherente por si misma. L ya esta bloqueada
     * ({@code FOR UPDATE}): {@code findById} devuelve la entidad gestionada.
     *
     * @param remaining miembros vigentes de L tras el movimiento
     */
    private void writeLosingGoldenRecord(PipelineContext ctx, String losingId, List<SourceRecordIdentity> remaining) {
        GoldenRecordEntity row = goldenRecordRepository.findById(UUID.fromString(losingId)).orElse(null);
        if (row == null || !isActiveStatus(row.getStatus())) {
            return; // absorbida, borrada, huerfana o inexistente: nada vigente que corregir
        }
        LosingGoldenRecordRecompute r = ctx.getLosingGoldenRecordRecompute();
        if (r == null || !r.goldenRecordId().equals(losingId) || r.expectedVersion() != row.getVersion()
                || !r.members().equals(Set.copyOf(remaining))) {
            goldenRecordCacheService.ifPresent(c -> c.evict(losingId));
            throw new OptimisticLockingFailureException("Golden record " + losingId + " losing "
                    + identity(ctx).display() + " changed since merge");
        }
        BigDecimal previousScore = row.getQualityScore();
        if (r.kind() == LosingGoldenRecordRecompute.Kind.ORPHAN) {
            row.setStatusEnum(GoldenRecordStatus.ORPHANED);
            row.setGoldenData(objectMapper.createObjectNode());
            row.setFieldLineage(objectMapper.createObjectNode());
            row.setQualityScore(null);
            row.setLatestSourceReceivedAt(null);
            row.setSourceCount(0);
        } else {
            row.setGoldenData(objectMapper.valueToTree(r.goldenData()));
            row.setFieldLineage(objectMapper.valueToTree(r.fieldLineage()));
            row.setQualityScore(BigDecimal.valueOf(r.qualityScore().score()));
            row.setLatestSourceReceivedAt(r.latestSourceReceivedAt());
            row.setSourceCount(r.members().size());
        }
        row.setPipelineRunId(ctx.getPipelineRunId());
        row.setUpdatedAt(Instant.now());
        row.setUpdatedBy(ctx.getUserId());
        goldenRecordRepository.saveAndFlush(row);
        ctx.addLosingGoldenRecordId(losingId);
        if (r.kind() == LosingGoldenRecordRecompute.Kind.RECOMPUTE) {
            emitTierChangeIfCrossed(losingId, previousScore, r.qualityScore(), ctx);
        }
    }

    /** Sin estado cuenta como activa (mismo criterio que {@link #isMissingOrOrphanUnderLock}). */
    private static boolean isActiveStatus(String status) {
        return status == null || GoldenRecordStatus.ACTIVE.getValue().equalsIgnoreCase(status);
    }
```

@DisplayName("Member loss — the golden record that loses a member is recomputed (RFC-PIPE-039)")

    // AC1, AC2
    @Test
    void forceRuleMoveOfTheWinningMemberRecomputesTheGoldenRecordItLeaves() throws Exception {
        String l = ingest(T1, "crm", "X1", lima("+34 611 000 001", "x1@lima.es")).gr();
        assertThat(ingest(T1, "erp_sap", "X2", lima("+34 611 000 002", "x2@lima.es")).gr()).isEqualTo(l);
        assertThat(ingest(T1, "web", "X3", lima("+34 611 000 003", "x3@lima.es")).gr()).isEqualTo(l);
        String f = ingest(T1, "crm", "Y", Map.of("legal_name", "Foxtrot Frio", "tax_id", "TF-1",
                "phone", "+34 622 000 001", "email", "y@foxtrot.es")).gr();
        assertThat(f).isNotEqualTo(l);
        assertThat(goldenData(l).get("email").asText()).isEqualTo(normalized("crm", "X1", "email"));
        jdbc.update("""
                UPDATE mdm_silver.staged_records SET quality_score = CASE source
                    WHEN 'crm' THEN 0.99 WHEN 'erp_sap' THEN 0.30 WHEN 'web' THEN 0.95 END
                WHERE tenant_id = ? AND source_record_id IN ('X1', 'X2', 'X3')""", T1);
        int versionBefore = version(l);

        insertForceRule(T1, "crm", "X1", f);
        assertThat(ingest(T1, "crm", "X1", lima("+34 611 000 001", "x1@lima.es")).gr()).isEqualTo(f);

        JsonNode data = goldenData(l);
        assertThat(data.get("email").asText()).as("source_priority: erp_sap after crm")
                .isEqualTo(normalized("erp_sap", "X2", "email"));
        assertThat(data.get("phone").asText()).as("highest_quality_score: web 0.95 over erp_sap 0.30")
                .isEqualTo(normalized("web", "X3", "phone"));
        JsonNode lineage = fieldLineage(l);
        assertThat(sourceRecordIds(lineage)).isNotEmpty().doesNotContain("X1");
        assertThat(version(l)).isGreaterThan(versionBefore);
        assertThat(sourceCount(l)).isEqualTo(2);
        assertThat(status(l)).isEqualTo("active");

        // AC2: el re-survivorship de administracion llega al mismo resultado
        Map<String, List<String>> coreBefore = lineageCore(lineage);
        mockMvc.perform(post("/api/v1/admin/re-survivorship/" + l)
                        .header("X-Tenant-Id", T1)
                        .header("X-User-Id", USER_ID))
                .andExpect(status().isOk());
        assertThat(goldenData(l)).isEqualTo(data);
        assertThat(lineageCore(fieldLineage(l))).isEqualTo(coreBefore);
    }

    // AC3
    @Test
    void forceRuleMoveOfTheLastMemberOrphansTheGoldenRecordItLeaves() throws Exception {
        String l = ingest(T1, "crm", "Z1", Map.of("legal_name", "Zulu Zapatos", "tax_id", "TZ-1",
                "phone", "+34 633 000 001", "email", "z1@zulu.es")).gr();
        String f = ingest(T1, "crm", "W", Map.of("legal_name", "Whisky Vinos", "tax_id", "TW-1",
                "phone", "+34 644 000 009", "email", "w@whisky.es")).gr();

        insertForceRule(T1, "crm", "Z1", f);
        assertThat(ingest(T1, "crm", "Z1", Map.of("legal_name", "Zulu Zapatos", "tax_id", "TZ-1",
                "phone", "+34 633 000 001", "email", "z1@zulu.es")).gr()).isEqualTo(f);

        Map<String, Object> row = jdbc.queryForMap("""
                SELECT status, golden_data::text AS gd, field_lineage::text AS fl, quality_score,
                       latest_source_received_at, source_count
                FROM mdm_gold.golden_records WHERE id = ?""", UUID.fromString(l));
        assertThat(row.get("status")).isEqualTo("orphaned");
        assertThat(objectMapper.readTree((String) row.get("gd")).isEmpty()).isTrue();
        assertThat(objectMapper.readTree((String) row.get("fl")).isEmpty()).isTrue();
        assertThat(row.get("quality_score")).isNull();
        assertThat(row.get("latest_source_received_at")).isNull();
        assertThat(row.get("source_count")).isEqualTo(0);
    }

    // ==================== fixtures ====================

    private static Map<String, Object> lima(String phone, String email) {
        return Map.of("legal_name", "Lima Logistica", "tax_id", "TL-1", "phone", phone, "email", email);
    }

    // ==================== helpers ====================

    private void registerSchema(String tenant, String version) throws Exception {
        JsonNode versioned = schema.deepCopy();
        ((ObjectNode) versioned.get("x-mdm")).put("version", version);
        mockMvc.perform(post("/api/v1/schemas")
                        .contentType(MediaType.APPLICATION_JSON)
                        .header("X-Tenant-Id", tenant)
                        .header("X-User-Id", USER_ID)
                        .content(objectMapper.writeValueAsString(Map.of("schema", versioned, "auto_activate", true))))
                .andExpect(status().isCreated());
    }

    private Ingested ingest(String tenant, String source, String srid, Map<String, Object> data) throws Exception {
        Map<String, Object> body = new LinkedHashMap<>();
        body.put("entity_type", ENTITY);
        body.put("source", source);
        body.put("source_record_id", srid);
        body.put("data", data);
        MvcResult r = mockMvc.perform(post("/api/v1/ingest/sync")
                        .contentType(MediaType.APPLICATION_JSON)
                        .header("X-Tenant-Id", tenant)
                        .header("X-User-Id", USER_ID)
                        .content(objectMapper.writeValueAsString(body)))
                .andReturn();
        assertThat(r.getResponse().getStatus()).as("ingest %s/%s: %s", source, srid,
                r.getResponse().getContentAsString()).isEqualTo(200);
        JsonNode json = objectMapper.readTree(r.getResponse().getContentAsString());
        assertThat(json.path("status").asText()).as("ingest %s/%s: %s", source, srid, json).isEqualTo("completed");
        return new Ingested(json.get("golden_record_id").asText(), json);
    }

    private void insertForceRule(String tenant, String source, String srid, String goldenRecordId) {
        jdbc.queryForObject("""
                INSERT INTO mdm_gold.force_rules
                    (tenant_id, entity_type, rule_type, source_record_id, source, golden_record_id, active, created_by)
                VALUES (?, ?, 'SOURCE_TO_GOLDEN', ?, ?, CAST(? AS uuid), true, 'test')
                RETURNING id::text""", String.class, tenant, ENTITY, srid, source, goldenRecordId);
        evictAllCaches();
    }

    /** Valor normalizado del campo en la ultima version en Silver del registro. */
    private String normalized(String source, String srid, String field) {
        return jdbc.queryForObject("""
                SELECT normalized_data ->> ? FROM mdm_silver.staged_records
                WHERE tenant_id = ? AND source = ? AND source_record_id = ?
                ORDER BY coalesce(received_at, created_at) DESC, created_at DESC LIMIT 1""",
                String.class, field, T1, source, srid);
    }

    private JsonNode goldenData(String gr) throws Exception {
        return objectMapper.readTree(jdbc.queryForObject(
                "SELECT golden_data::text FROM mdm_gold.golden_records WHERE id = ?", String.class, UUID.fromString(gr)));
    }

    private JsonNode fieldLineage(String gr) throws Exception {
        return objectMapper.readTree(jdbc.queryForObject(
                "SELECT field_lineage::text FROM mdm_gold.golden_records WHERE id = ?", String.class, UUID.fromString(gr)));
    }

    /** Todos los source_record_id del linaje, incluidos los de competing_values. */
    private static List<String> sourceRecordIds(JsonNode lineage) {
        List<String> ids = new ArrayList<>(lineage.findValuesAsText("source_record_id"));
        ids.addAll(lineage.findValuesAsText("sourceRecordId"));
        return ids;
    }

    /** Por campo: value, source, source_record_id y rule_applied (sin resolved_at ni confidence). */
    private static Map<String, List<String>> lineageCore(JsonNode lineage) {
        Map<String, List<String>> core = new LinkedHashMap<>();
        for (Iterator<Map.Entry<String, JsonNode>> it = lineage.fields(); it.hasNext(); ) {
            Map.Entry<String, JsonNode> e = it.next();
            JsonNode v = e.getValue();
            core.put(e.getKey(), List.of(v.path("value").toString(), v.path("source").asText(),
                    v.path("source_record_id").asText(v.path("sourceRecordId").asText()),
                    v.path("rule_applied").asText(v.path("ruleApplied").asText())));
        }
        return core;
    }

    private int version(String gr) {
        return jdbc.queryForObject("SELECT version FROM mdm_gold.golden_records WHERE id = ?",
                Integer.class, UUID.fromString(gr));
    }

    private int sourceCount(String gr) {
        return jdbc.queryForObject("SELECT source_count FROM mdm_gold.golden_records WHERE id = ?",
                Integer.class, UUID.fromString(gr));
    }

    private String status(String gr) {
        return jdbc.queryForObject("SELECT status FROM mdm_gold.golden_records WHERE id = ?",
                String.class, UUID.fromString(gr));
    }
}
