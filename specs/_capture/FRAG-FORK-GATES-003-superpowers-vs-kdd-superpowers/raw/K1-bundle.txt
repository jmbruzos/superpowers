# WRK-PLAN-MDM-MEMBER-LEAVE-001 — La ficha que pierde un miembro se recalcula

> **For agentic workers:** REQUIRED SUB-SKILL: Use kdd-superpowers:subagent-driven-development (recommended) or kdd-superpowers:executing-plans to implement this plan task-by-task. Each task is its own WRK-TASK file under `specs/work/`; steps use checkbox (`- [ ]`) syntax for tracking.

## Approach

**Goal:** cuando una ForceRule saca un registro de la ficha L en el pipeline, L se recalcula con survivorship sobre
sus miembros vigentes (o pasa a `orphaned`) en la misma transacción, desactiva los pins que apuntaban al registro, sube
su versión y lo notifica tras el commit.

**Architecture:** dos puertos nuevos de mdm-core (versiones en Silver de un conjunto de miembros; desactivación de
source pins) con adaptadores en mdm-persistence; un componente sin JPA en mdm-ingest-service
(`MemberSurvivorshipRecomputer`) que encadena el `MergeEngine` como la re-survivorship de stewardship y rellena
`previous`; y `PersistenceStepHandler`, que ya bloquea L, aplica la regla sobre la entidad bloqueada y registra los
eventos con `TransactionSynchronization.afterCommit` (el patrón de `ConsolidationOverrideMigrator`). Cada intento de
persistence es su propia transacción (`PipelineOrchestrator.java:322`), así que un intento revertido no publica nada:
no hace falta la lista por intento en `PipelineContext` que el §2 de la WRK-SPEC listaba (ver *Desviaciones*).

**Tech Stack:** Java 21, Spring Boot 3.4, Spring Data JPA, JUnit 5 + AssertJ + Mockito, Testcontainers PostgreSQL,
Maven multi-módulo (`src/pom.xml`).

**Spec:** `specs/work/WRK-SPEC-MDM-MEMBER-LEAVE-001-la-ficha-que-pierde-un-miembro-se-recalcula.md` — el plan argumenta
desde la spec; los ejecutores leen las dos.

# WRK-SPEC-MDM-MEMBER-LEAVE-001 — La ficha que pierde un miembro se recalcula

Resuelve RFC-PIPE-039. Cluster `work:manual-unification` (ADR-011).

## Problem Statement

Cuando un registro de origen sale de una ficha (se cierra su tramo vigente en `mdm_gold.source_record_xref`), la
ficha que lo pierde debe dejar de mostrar lo que aportaba ese registro. Hoy (FRAG-MDM-MEMBER-LEAVE-001):

- **Unmerge**: correcto. La ficha original se recalcula con survivorship sobre los miembros que quedan y su
  `field_lineage` se reemplaza entero (`StewardshipService.java:435`, `:457-459`). No puede quedarse sin miembros
  (`:2256-2258`).
- **Movimiento por ForceRule en el pipeline** (`PersistenceStepHandler.persistMembership`, rama `FORCED`,
  `:777-780`, `:806-809`): la ficha que pierde el miembro (`previous`) solo ve limpiadas sus blocking keys, recalculado
  su `source_count` y evictada la caché local. `golden_data`, `field_lineage`, `quality_score` y
  `latest_source_received_at` conservan los valores del que se fue; su `@Version` no sube; no se publica
  `golden_record.updated`. Si era su único miembro, la ficha queda `active` con `source_count = 0`, sin claves y con
  los datos del registro que ya vive en otra ficha — nadie escribe `orphaned`.
- **Resolución de revisión**: `MembershipOperationKind.REVIEW_RESOLUTION` está declarado pero ninguna ruta de
  producción cierra tramos con él (WRK-SPEC 3, OQ-3 de WRK-SPEC-MDM-SOURCE-IDENTITY-001).

Consecuencia: un consumidor lee en la ficha un email o un NIF que ya pertenece a otra; una actualización concurrente
de la ficha calculada sobre esos datos no choca con la guarda de versión, porque la versión no sube.

## Proposed Change

### 1. Regla — la ficha que pierde un miembro en el pipeline

Alcance: los cierres de tramo del **pipeline** (`PersistenceStepHandler.persistMembership`), que hoy son la única ruta
que deja una ficha `active` sin recalcular (FRAG-MDM-MEMBER-LEAVE-001). El unmerge ya cumple la regla y no cambia; la
resolución de revisión (WRK-SPEC 3) queda en OQ-3.

Tras `move` y la limpieza de claves, **en la misma transacción** y bajo el bloqueo `FOR UPDATE` que ya tiene la ficha L
que pierde el miembro X:

| Estado de L | Qué se hace con L |
|---|---|
| `active`, ≥ 1 miembro vigente con versión en Silver | **Recálculo completo**: survivorship sobre **todas** las versiones en Silver de sus miembros vigentes (mismas entradas que la re-survivorship de DOM-MDM-SURVIVORSHIP-001 §3.8.2 y que el unmerge). Se reemplazan `golden_data`, `field_lineage`, `quality_score` y `latest_source_received_at` (candidato de "recálculo completo", §3.7.1.1). En cada campo cuyo valor cambia respecto al persistido, `field_lineage.<campo>.previous` = `{value, source}` del lineage persistido de L, `changed_at` = instante de la operación, `changed_by_pipeline_run` = run actual (§3.6.1). Se desactivan los pins (§1.1). Se guarda la entidad (sube `@Version`). |
| `active`, ≥ 1 miembro vigente, **ninguno** con versión en Silver | L **no se escribe**: conserva `golden_data`, `field_lineage`, `quality_score`, `latest_source_received_at` y versión; se desactivan los pins (§1.1) y se registra un WARN con tenant, L y X. (Hoy solo ocurre con datos anteriores a la xref.) |
| `active`, **sin** miembros vigentes | **Pasa a `orphaned`** (DOM-MDM-SURVIVORSHIP-001 §3.2). `golden_data`, `field_lineage` y `quality_score` se conservan como lectura histórica; se desactivan los pins (§1.1); se guarda (sube `@Version`). |
| `absorbed`, `orphaned`, `deleted` o inexistente | Nada (comportamiento actual). |

**1.1 Pins.** Se desactivan los `source_pin` activos de L cuyo registro fijado es X: `pinned_source = X.source` y
`pinned_source_record_id = X.source_record_id`, o `pinned_source` nulo (legado) con el mismo id — el mismo criterio que
`autoDeactivatePins` del unmerge. `deactivation_reason = "member_left"`, `deactivated_by = "system:pipeline"`, y tras el
commit se publica `FieldOverrideAutoDeactivated` (DOM-MDM-PIPELINE-001 §10.9.4 p.2), como `ConsolidationOverrideMigrator`.
Los value overrides no se tocan: en el recálculo se siguen aplicando vía `FieldOverrideProvider`; en una ficha
`orphaned` quedan inertes (no participa en merge).

**1.2 Eventos, tras el commit y solo si el run hace commit.**
- L recalculada: `golden_record.updated` con la firma actual de `IngestEventEmitter.emitGoldenRecordUpdated` (sin campo
  `reason`); invalida la caché en todos los pods (`CacheInvalidationListener`). Si el tier de L cambia (score
  persistido antes → score nuevo de L; un score nulo parte de 0.5, §3.3.6), `GoldenRecordQualityChanged` para L.
- L `orphaned`: evento nuevo `golden_record.orphaned` (aggregate `golden_record`, payload `goldenRecordId`, `entityType`,
  `sourceRecord` = identidad de X) — la notificación análoga a la de absorción; **no** `golden_record.updated`, porque
  una ficha `orphaned` no propaga actualizaciones (§3.2). `CacheInvalidationListener` también evicta con él.
- Las fichas que perdieron un miembro se acumulan por **intento** de persistence: la lista se vacía cuando el
  orquestador limpia la salida de merge para reintentar (`clearMergeOutput`), así que un intento revertido no deja
  eventos.

**1.3 Superviviente de merge manual.** Si L tiene una ForceRule `GOLDEN_TO_GOLDEN` activa, **también** se recalcula. El
filtro de PROD-MDM-STEWARDSHIP-001 §3.8.5 acota las rutas de re-survivorship de administración ("ambas rutas"); aquí
conservar los valores de X es el defecto a corregir. Consecuencia aceptada: los valores de los miembros que llegaron
por el merge manual pueden ganar campos por primera vez (OQ-2).

### 2. Componentes

- **Puerto `SourceRecordVersionReader.findVersionsOfMembers(tenantId, entityType, members)`** (mdm-core): todas las
  versiones en Silver de un conjunto de identidades, en el orden de `StagedRecordJpaRepository.findVersionsOfMembers`
  (`coalesce(received_at, created_at)`, `source_record_id`, `source`, `created_at`, ascendente). `SourceRecordVersion`
  gana `qualityScore` (nullable). Implementación en mdm-persistence sobre la consulta existente.
- **Puerto `SourcePinDeactivator`** (mdm-core; implementación en mdm-persistence): desactiva los pins de §1.1 y devuelve
  los desactivados (para el evento).
- **`MemberSurvivorshipRecomputer`** (mdm-ingest-service; solo puertos de mdm-core, `MergeEngine`,
  `QualityScoreResolver`, `LatestSourceReceivedAtResolver`): `recompute(tenantId, entityType, goldenRecordId,
  survivorshipConfig, persistedGoldenData, persistedLineage, evaluationInstant, runId)` → `Recomputed(mergeResult,
  latestSourceReceivedAt, qualityScore)` | `NoMembers` | `NoVersions`. Encadena `MergeEngine.merge` (`create` para la
  primera versión, `update` para el resto; confianza 1.0; `qualityScore` de la versión o 0.8) — el mismo algoritmo que
  `StewardshipService.reSurvivorshipFromSources` — y rellena `previous` según §1.
- **`StewardshipService` no cambia.** La equivalencia de los dos encadenados la fija un test de paridad (AC9).
- **`PersistenceStepHandler.persistMembership`**: tras `move` + `cleanUpAfterLosingMember`, si L está `active` aplica §1
  sobre la entidad bloqueada (`saveAndFlush`), y registra en el contexto la ficha, su score anterior y nuevo, y los pins
  desactivados.
- **`PipelineContext`**: lista por intento de fichas que perdieron un miembro; `clearMergeOutput` la vacía.
- **Emisión post-commit** (`IngestService`, `AsyncPipelineExecutor`): recorre esa lista y emite los eventos de §1.2.
- **`CacheInvalidationListener`** (mdm-app): evicta también con `golden_record.orphaned`.

### 3. Flujo de datos

Match resuelve `FORCED` con `conflictFromGoldenRecordId = L` → merge sobre F → persistence: bloqueo de F y L en orden
de id (ya existe) → escritura de F → `move` (cierra en L, abre en F) → limpieza de claves de L → **§1 sobre L** →
`refreshSourceCounts({F, L})` → commit → eventos de F (actuales) y de L (§1.2).

### 4. Errores y concurrencia

- Un fallo del recálculo lanza dentro de la transacción de persistence: se revierte el paso entero y aplica ADR-013;
  agotados los reintentos, el run va a la DLQ relanzable (ADR-016). No hay degradación a "marcar para recálculo".
- La subida de `@Version` de L hace fallar la guarda de ADR-020 de cualquier run concurrente que calculó un merge sobre
  L con los datos antiguos, que retrocede a Merge con lectura fresca (DOM-MDM-PIPELINE-001 §6.5).

### 5. Pruebas

- Unitarias: `MemberSurvivorshipRecomputerTest` (encadenado, `previous`, frescura, score, `NoMembers`, `NoVersions`);
  `PersistenceStepHandlerTest` (rama FORCED en los cuatro estados de §1; pins; registro por intento).
- Integración (Testcontainers): `SourceIdentityPipelineIT` (AC1–AC7), `StewardshipFlowsIT` (AC8), un IT de paridad
  (AC9), ITs de los adaptadores de los dos puertos.

package com.mdm.persistence.repository;

import com.mdm.core.domain.membership.SourceRecordIdentity;
import com.mdm.core.repository.SourcePinDeactivator;
import com.mdm.persistence.entity.FieldOverrideRuleEntity;
import org.springframework.stereotype.Repository;

import java.time.Instant;
import java.util.ArrayList;
import java.util.List;
import java.util.UUID;

/** Adaptador de {@link SourcePinDeactivator} sobre {@link FieldOverrideRuleJpaRepository}. */
@Repository
public class SourcePinDeactivatorAdapter implements SourcePinDeactivator {

    private static final String SOURCE_PIN = "SOURCE_PIN";

    private final FieldOverrideRuleJpaRepository repository;

    public SourcePinDeactivatorAdapter(FieldOverrideRuleJpaRepository repository) {
        this.repository = repository;
    }

    @Override
    public List<DeactivatedPin> deactivatePinsOf(String tenantId, String goldenRecordId, SourceRecordIdentity member,
                                                 String reason, String actor, Instant at) {
        List<DeactivatedPin> deactivated = new ArrayList<>();
        for (FieldOverrideRuleEntity pin : repository.findByGoldenRecordIdAndTenantIdAndActiveAndOverrideType(
                UUID.fromString(goldenRecordId), tenantId, true, SOURCE_PIN)) {
            boolean sameRecord = member.sourceRecordId().equals(pin.getPinnedSourceRecordId())
                    && (pin.getPinnedSource() == null || member.source().equals(pin.getPinnedSource()));
            if (!sameRecord) {
                continue;
            }
            pin.setActive(false);
            pin.setDeactivatedAt(at);
            pin.setDeactivatedBy(actor);
            pin.setDeactivationReason(reason);
            repository.saveAndFlush(pin);
            deactivated.add(new DeactivatedPin(pin.getField(), pin.getPinnedSourceRecordId()));
        }
        return deactivated;
    }
}

Componente sin JPA en mdm-ingest-service que recalcula una ficha desde sus miembros vigentes: lee la xref, lee todas

import com.mdm.core.domain.membership.MembershipSpan;
import com.mdm.core.domain.membership.SourceRecordIdentity;
import com.mdm.core.domain.merge.FieldLineageEntry;
import com.mdm.core.domain.merge.FieldLineageEntry.FieldLineagePrevious;
import com.mdm.core.domain.merge.MergeResult;
import com.mdm.core.domain.schema.SurvivorshipConfig;
import com.mdm.core.repository.SourceMembershipRepository;
import com.mdm.core.repository.SourceRecordVersionReader;
import com.mdm.core.repository.SourceRecordVersionReader.MemberVersion;
import com.mdm.engine.merge.MergeEngine;
import com.mdm.engine.merge.MergeRequest;
import com.mdm.ingest.quality.LatestSourceReceivedAtResolver;
import com.mdm.ingest.quality.QualityScoreResolver;
import com.mdm.ingest.quality.QualityScoreResolver.QualityScoreInput;
import com.mdm.ingest.quality.QualityScoreResolver.QualityScoreResult;
import org.springframework.stereotype.Component;

import java.time.Instant;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import java.util.Objects;

/**
 * Recalcula una ficha desde sus miembros vigentes de la xref (WRK-SPEC-MDM-MEMBER-LEAVE-001 §1-2): survivorship
 * completa sobre todas sus versiones en Silver, con el mismo encadenado que la re-survivorship de stewardship
 * (DOM-MDM-SURVIVORSHIP-001 §3.8.2), frescura de "recalculo completo" (§3.7.1.1) y {@code previous} en los campos que
 * cambian respecto a lo persistido (§3.6.1). No escribe: el llamante decide que hacer con el resultado.
 *
 * <p>Recibe el {@link MergeEngine} bean para que los overrides activos de la ficha se sigan aplicando
 * (PROD-MDM-STEWARDSHIP-001 §3.8.5). Confianza 1.0 por miembro, como stewardship (OQ-1 de la WRK-SPEC).
 */
@Component
public class MemberSurvivorshipRecomputer {

    private static final double TRUST = 1.0;
    private static final double DEFAULT_VERSION_QUALITY = 0.8;

    private final SourceMembershipRepository membership;
    private final SourceRecordVersionReader versions;
    private final MergeEngine engine;
    private final QualityScoreResolver qualityScoreResolver;
    private final LatestSourceReceivedAtResolver latestSourceReceivedAtResolver;

    public MemberSurvivorshipRecomputer(SourceMembershipRepository membership, SourceRecordVersionReader versions,
                                        MergeEngine engine, QualityScoreResolver qualityScoreResolver,
                                        LatestSourceReceivedAtResolver latestSourceReceivedAtResolver) {
        this.membership = membership;
        this.versions = versions;
        this.engine = engine;
        this.qualityScoreResolver = qualityScoreResolver;
        this.latestSourceReceivedAtResolver = latestSourceReceivedAtResolver;
    }

    /** Entrada del recalculo; {@code persistedLineage} es el lineage de la ficha antes de perder el miembro. */
    public record Request(String tenantId, String entityType, String goldenRecordId,
                          SurvivorshipConfig survivorshipConfig,
                          Map<String, FieldLineageEntry> persistedLineage,
                          Instant evaluationInstant, String pipelineRunId) {}

    public sealed interface Outcome permits Recomputed, NoMembers, NoVersions {}

    public record Recomputed(Map<String, Object> goldenData, Map<String, FieldLineageEntry> fieldLineage,
                             Instant latestSourceReceivedAt, QualityScoreResult quality) implements Outcome {}

    /** La ficha no tiene miembros vigentes: pasa a {@code orphaned} (DOM-MDM-SURVIVORSHIP-001 §3.2). */
    public record NoMembers() implements Outcome {}

    /** Tiene miembros vigentes pero ninguno con version en Silver (datos anteriores a la xref). */
    public record NoVersions(int members) implements Outcome {}

    public Outcome recompute(Request r) {
        List<SourceRecordIdentity> members = membership.findCurrentMembers(r.tenantId(), r.goldenRecordId()).stream()
                .map(MembershipSpan::identity).toList();
        if (members.isEmpty()) {
            return new NoMembers();
        }
        List<MemberVersion> all = versions.findVersionsOfMembers(r.tenantId(), r.entityType(), members);
        if (all.isEmpty()) {
            return new NoVersions(members.size());
        }
        MergeResult merged = chain(all, r);
        Map<String, FieldLineageEntry> lineage = withPrevious(merged.fieldLineage(), r.persistedLineage(),
                r.evaluationInstant(), r.pipelineRunId());
        Instant latest = latestSourceReceivedAtResolver.resolve(all.stream().map(MemberVersion::receivedAt).toList());
        QualityScoreResult quality = qualityScoreResolver.resolve(new QualityScoreInput(r.tenantId(), r.entityType(),
                merged.goldenData(), lineage, latest, r.evaluationInstant()));
        return new Recomputed(merged.goldenData(), lineage, latest, quality);
    }

    /** El encadenado de {@code StewardshipService.reSurvivorshipFromSources}: create y despues update, en orden. */
    private MergeResult chain(List<MemberVersion> all, Request r) {
        MergeResult result = null;
        for (MemberVersion v : all) {
            boolean first = result == null;
            result = engine.merge(new MergeRequest(
                    first ? "create" : "update", v.normalizedData(),
                    first ? null : result.goldenData(), first ? null : result.fieldLineage(),
                    r.survivorshipConfig(), v.identity().source(), v.identity().sourceRecordId(),
                    TRUST, v.qualityScore() != null ? v.qualityScore() : DEFAULT_VERSION_QUALITY,
                    r.pipelineRunId(), r.goldenRecordId(), r.tenantId(), null, null, null));
        }
        return result;
    }

    /**
     * {@code previous} solo en los campos cuyo valor cambia respecto al lineage persistido (§3.6.1); se compara el
     * {@code value} del lineage por clave, no {@code golden_data}, para cubrir rutas anidadas.
     */
    private static Map<String, FieldLineageEntry> withPrevious(Map<String, FieldLineageEntry> recomputed,
                                                               Map<String, FieldLineageEntry> persisted,
                                                               Instant at, String runId) {
        Map<String, FieldLineageEntry> out = new LinkedHashMap<>();
        recomputed.forEach((field, e) -> {
            FieldLineageEntry before = persisted != null ? persisted.get(field) : null;
            FieldLineagePrevious previous = before != null && !Objects.equals(before.value(), e.value())
                    ? FieldLineagePrevious.of(before.value(), before.source(), at, runId)
                    : null;
            out.put(field, new FieldLineageEntry(e.value(), e.source(), e.sourceRecordId(), e.ruleApplied(),
                    e.resolvedAt(), e.confidence(), e.conflict(), e.competingValues(), previous));
        });
        return out;
    }
}

    /**
     * Regla de la ficha que pierde un miembro (WRK-SPEC-MDM-MEMBER-LEAVE-001 §1): sobre la fila L ya bloqueada, si
     * sigue {@code active}, desactiva los source pins del registro que sale y la recalcula con survivorship sobre
     * sus miembros vigentes (o la marca {@code orphaned} si no le quedan; sin versiones en Silver, no se escribe).
     * Guardar sube su {@code @Version}: un run concurrente que calculo un merge sobre L con los datos anteriores
     * falla la guarda de ADR-020 (DOM-MDM-PIPELINE-001 §6.5). Los eventos se publican tras el commit del intento.
     */
    private void applyMemberLeftRule(PipelineContext ctx, SourceRecordIdentity left, Optional<GoldenRecordEntity> row) {
        if (memberRecomputer == null || row.isEmpty() || !isActive(row.get())) {
            return;
        }
        GoldenRecordEntity l = row.get();
        String lId = l.getId().toString();
        Instant now = Instant.now();
        deactivatePinsOf(ctx, lId, left, now);
        MemberSurvivorshipRecomputer.Outcome outcome = memberRecomputer.recompute(new MemberSurvivorshipRecomputer.Request(
                ctx.getTenantId(), ctx.getEntityType(), lId, ctx.getSurvivorshipConfig(), persistedLineage(l), now,
                ctx.getPipelineRunId()));
        switch (outcome) {
            case MemberSurvivorshipRecomputer.Recomputed r -> {
                BigDecimal previousScore = l.getQualityScore();
                l.setGoldenData(objectMapper.valueToTree(r.goldenData()));
                l.setFieldLineage(objectMapper.valueToTree(r.fieldLineage()));
                l.setLatestSourceReceivedAt(r.latestSourceReceivedAt());
                l.setQualityScore(BigDecimal.valueOf(r.quality().score()));
                l.setUpdatedAt(now);
                goldenRecordRepository.saveAndFlush(l);
                producedEdge(ctx, lId, "member_left", now);
                afterCommit(() -> ingestEventEmitter.emitGoldenRecordUpdated(lId, ctx.getEntityType(),
                        ctx.getSource(), ctx.getTenantId(), ctx.getUserId()));
                tierChangeAfterCommit(ctx, lId, previousScore, r.quality());
            }
            case MemberSurvivorshipRecomputer.NoMembers n -> {
                l.setStatusEnum(GoldenRecordStatus.ORPHANED);
                l.setUpdatedAt(now);
                goldenRecordRepository.saveAndFlush(l);
                producedEdge(ctx, lId, "member_left_orphaned", now);
                afterCommit(() -> ingestEventEmitter.emitGoldenRecordOrphaned(lId, ctx.getEntityType(), left.source(),
                        left.sourceRecordId(), ctx.getPipelineRunId(), ctx.getSource(), ctx.getTenantId(),
                        ctx.getUserId()));
            }
            case MemberSurvivorshipRecomputer.NoVersions nv ->
                    log.warn("Golden record {} lost member {} and keeps its data: none of its {} current members has a "
                            + "Silver version (tenant {})", lId, left.display(), nv.members(), ctx.getTenantId());
        }
    }

    /**
     * {@code PRODUCED} run → L: el run modifico L (DOM-MDM-LINEAGE-001 §3.2.5, "Update de golden record | Añade
     * {@code PRODUCED}"). {@code action = updated}; {@code reason} distingue el recalculo del paso a {@code orphaned}.
     */
    private void producedEdge(PipelineContext ctx, String lId, String reason, Instant now) {
        if (graphStore == null) {
            return;
        }
        graphStore.addEdge(new LineageEdge(null, "PipelineRun", ctx.getPipelineRunId(), "GoldenRecord", lId,
                LineageEdgeType.PRODUCED, ctx.getTenantId(), now, Map.of("action", "updated", "reason", reason)));
    }

    private static boolean isActive(GoldenRecordEntity gr) {
        return gr.getStatus() == null || GoldenRecordStatus.ACTIVE.getValue().equalsIgnoreCase(gr.getStatus());
    }

    /** Pins de L sobre el registro que sale (§1.1), con {@code FieldOverrideAutoDeactivated} tras el commit. */
    private void deactivatePinsOf(PipelineContext ctx, String lId, SourceRecordIdentity left, Instant now) {
        if (pinDeactivator == null) {
            return;
        }
        for (SourcePinDeactivator.DeactivatedPin pin : pinDeactivator.deactivatePinsOf(ctx.getTenantId(), lId, left,
                SourcePinDeactivator.REASON_MEMBER_LEFT, SourcePinDeactivator.ACTOR_PIPELINE, now)) {
            afterCommit(() -> ingestEventEmitter.emitFieldOverrideAutoDeactivated(lId, ctx.getEntityType(),
                    pin.field(), "SOURCE_PIN", SourcePinDeactivator.REASON_MEMBER_LEFT, null,
                    pin.pinnedSourceRecordId(), ctx.getPipelineRunId(), ctx.getSource(), ctx.getTenantId()));

    /** Cruce de tier de L con su score anterior y el recalculado (DOM-MDM-SURVIVORSHIP-001 §3.7.3; nulo = 0.5). */
    private void tierChangeAfterCommit(PipelineContext ctx, String lId, BigDecimal previousScore,
                                       QualityScoreResult now) {
        double previous = previousScore != null ? previousScore.doubleValue() : 0.5;
        String previousTier = qualityScoreResolver.tierFor(ctx.getTenantId(), ctx.getEntityType(), previous);
        if (previousTier.equals(now.tier())) {
            return;
        }
        afterCommit(() -> {
            ingestEventEmitter.emitGoldenRecordQualityChanged(lId, ctx.getEntityType(), previous, now.score(),
                    previousTier, now.tier(), ctx.getPipelineRunId(), ctx.getSource(), ctx.getTenantId(),
                    ctx.getUserId());
            Metrics.counter("mdm_golden_record_quality_tier_changes_total",
                    "entity_type", ctx.getEntityType(), "from_tier", previousTier, "to_tier", now.tier()).increment();
        });
    }

    /** Lineage persistido de L, entrada a entrada: una entrada ilegible se descarta con WARN, el resto se conserva. */
    private Map<String, FieldLineageEntry> persistedLineage(GoldenRecordEntity gr) {
        Map<String, FieldLineageEntry> out = new LinkedHashMap<>();
        JsonNode node = gr.getFieldLineage();
        if (node == null || !node.isObject()) {
            return out;
        }
        node.fields().forEachRemaining(f -> {
            try {
                out.put(f.getKey(), objectMapper.treeToValue(f.getValue(), FieldLineageEntry.class));
            } catch (Exception e) {
                log.warn("Unreadable field_lineage entry '{}' of golden record {}: {}", f.getKey(), gr.getId(),
                        e.getMessage());
            }
        });
        return out;
    }

    /** Tras el commit del intento (cada intento es su propia transaccion); sin transaccion, en el acto. */
    private static void afterCommit(Runnable action) {
        if (TransactionSynchronizationManager.isSynchronizationActive()) {
            TransactionSynchronizationManager.registerSynchronization(new TransactionSynchronization() {
                @Override public void afterCommit() { action.run(); }
            });
        } else {
            action.run();
        }
    }
